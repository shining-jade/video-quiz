## 1. 현재 상태

- 기존 Firebase Realtime Database 사용 코드를 Cloud Firestore 기반으로 이전했다.
- Firebase 프로젝트 `video-quiz-65798`의 Firestore를 사용한다.
- GitHub Pages가 `main` 브랜치 루트를 배포한다.
- 교사는 Google 로그인과 비공개 승인 목록을 통과해야 하고, 학생은 기존 6자리 코드와 익명 UID 흐름을 유지한다.
- 최신 공개 사이트에서 홈 메뉴 4열 배치와 브라우저 오류·경고 0건을 확인했다.
- 교사용 전체화면 진행 모드와 다중 영상 플레이리스트는 현재 `codex/multi-video-quiz-playlist` 기능 브랜치에 통합되어 있다.
- 이 통합 브랜치는 로컬 검증 중이며, `main` 병합과 GitHub Pages 공개 배포 검증은 최종 리뷰 뒤 수행해야 한다.

## 2. Firestore 이전

### 데이터 구조

```text
quiz_sets/{setId}
    videos[]                              { videoId, videoUrl, startSec, endSec, questions[] }
images/{setId}/q/v{videoIndex}q{questionIndex}
codes/{code}
sessions/{sessionId}
sessions/{sessionId}/meta/live
sessions/{sessionId}/meta/board
sessions/{sessionId}/students/{studentId}
sessions/{sessionId}/responses/{studentId}
sessions/{sessionId}/snapshot/set
sessions/{sessionId}/snapshot_images/v{videoIndex}q{questionIndex}
clock/{sampleId}
teacher_allowlist/{verifiedEmail}
```

단일 영상 형식의 기존 세트는 읽을 때 최상위 `videoId`·`videoUrl`·`questions[]`를 `videos[0]`으로 정규화하고, 구간은 `startSec: 0`, `endSec: null`로 간주한다. 이미지 문서의 표준 키는 `v0q0`, `v1q2`처럼 영상·문항 인덱스를 함께 담는다. 첫 영상의 이전 숫자 키(`0`, `1`, …)도 읽기 fallback으로 유지해 기존 이미지가 사라지지 않는다.

주요 구현 파일:

- `firestore-core.js`: 데이터 변환, 점수·제출 인원 계산, 서버 시각 기반 타이머 계산
- `firestore-store.js`: Firestore 문서·컬렉션 읽기/쓰기/구독, 세션과 응답 저장
- `firestore.rules`: 배포용 Firestore 보안 규칙
- `index.html`: 교사·학생·관리자 화면과 전체 사용자 흐름

운영 특이사항:

- 교사는 검증된 Google 계정과 `teacher_allowlist/{email}`의 `enabled: true`, `role: teacher|admin`을 모두 통과해야 한다. 승인 목록은 클라이언트 get/list/write가 전부 거부된다.
- 일반 교사는 자기 세트와 세션만 변경한다. 승인 교사는 다른 교사의 공유 세트를 읽고 수업 또는 사본 생성에 사용할 수 있으나 원본을 편집하지 못한다. `admin`은 전체 세션 조회·삭제 권한을 갖지만 콘텐츠 소유권을 자동으로 얻지 않는다.
- 학생은 참여 경로에서만 익명 인증하고, 자기 UID 문서와 `meta/live`의 안전한 공개 문항만 읽는다. 공개 전 정답·해설, 원본 세트, 다른 학생 응답과 교사 전용 grade는 거부된다.
- 학생 화면은 주로 `sessions/{sessionId}/meta/live` 한 문서를 실시간 구독해 읽기 비용을 줄였다.
- 반 코드는 트랜잭션으로 선점하여 동시 생성 충돌을 방지한다.
- Firestore 서버 시각 보정값과 `openedAt`을 사용해 교사·학생 타이머를 동기화한다.

### 승인 계정과 레거시 이전 운영 절차

1. Firebase Authentication에서 Google과 Anonymous 공급자를 사용 설정한다.
2. `teacher_allowlist/{정규화 이메일}`에 `enabled: true`, `role: teacher|admin`을 신뢰할 수 있는 환경에서 등록한다.
3. Admin SDK 자격 증명이 있는 로컬 터미널에서 먼저 dry-run 한다.

   ```powershell
   pnpm migrate:legacy -- --project video-quiz-65798 --owner-uid <교사_UID> --output migration-dry-run.json
   ```

4. 실패·감사 실패·모호한 커밋 재확인·남은 응답 누출이 모두 0인지 검토한 뒤 정확한 프로젝트 ID로 apply 한다.

   ```powershell
   pnpm migrate:legacy -- --project video-quiz-65798 --owner-uid <교사_UID> --apply --confirm-project video-quiz-65798 --provision-owner-email teacher@school.kr --output migration-apply.json
   ```

5. 일부 실패는 새 출력 파일명으로 같은 명령을 재실행한다. 이미 이전된 문서는 건너뛴다. 최종 보고서의 `safeToDeployStrictRules: true`를 확인하기 전에는 엄격한 규칙을 게시하지 않는다.
6. 규칙 게시 전 원문과 릴리스 시각을 보관한다. 문제 시 데이터는 되돌리지 않고 Firebase Console의 Firestore 규칙 릴리스 기록에서 직전 규칙을 복원·게시한다.

## 3. 퀴즈 편집 저장 방식

- 저장 버튼 또는 `Ctrl+S`/`Cmd+S`를 누르면 Firestore에 정식 저장한다.
- 편집 중 변경 사항은 현재 브라우저의 로컬 저장소에 임시 초안으로 자동 보관한다.
- 새 세트와 기존 세트의 초안을 구분하며 기존 세트는 세트 ID별로 분리한다.
- 다시 편집 화면에 들어왔을 때 로컬 초안이 서버 저장본보다 최신이면 복구 여부를 묻는다.
- 정식 저장이 성공하면 해당 로컬 초안을 삭제한다.
- 저장 상태는 `저장하지 않은 변경`, `저장 중…`, `저장됨`, `저장 실패`로 표시한다.
- 제목·설정·문항 내용뿐 아니라 문항 추가·삭제·이동 같은 구조 변경도 초안에 반영한다.

## 4. 학생 답안 제출 흐름

- 객관식 번호 선택, O/X 선택, 복수 선택, 텍스트 입력만으로는 제출되지 않는다.
- 학생이 `제출하기` 버튼을 눌러야 답이 확정된다.
- 제한 시간이 남아 있으면 `다시 고르기`로 제출을 취소하고 수정할 수 있다.
- 제한 시간이 끝날 때 선택하거나 입력한 답이 있으면 제출 버튼을 누르지 않아도 자동 제출한다.
- 마감 시 아무 답도 없으면 미제출로 남는다.
- 마감 순간 화면 잠금과 자동 제출이 겹쳐도 선택 답이 한 번 저장되도록 회귀 테스트가 있다.
- 정답 공개 또는 문항 종료 뒤에는 답을 수정할 수 없다.

Firestore 응답에는 문항별 답과 함께 제출 상태를 기록한다. 이전 데이터에 제출 상태 필드가 없으면 기존 호환을 위해 제출된 답으로 간주한다.

## 5. 교사 화면과 동기화 타이머

- 교사 화면에서 현재 문항의 `참여`, `제출`, `미제출` 인원을 실시간으로 표시한다.
- 참여는 세션에 입장한 학생 수, 제출은 현재 문항을 확정한 학생 수, 미제출은 그 차이다.
- 정답 공개 전에는 답 분포와 정답을 숨기고 제출 인원만 보여준다.
- 교사와 학생 화면에 동일한 가로형 진행 막대와 남은 시간 숫자를 표시한다.
- 타이머 색상은 기본 초록, 7초 이하 주황, 3초 이하 빨강으로 변한다.
- 두 화면 모두 같은 Firestore 서버 시각 기준으로 계산한다.
- `prefers-reduced-motion` 환경에서는 움직임을 줄인다.

## 7. 교사용 전체화면 진행 모드

새 구조:

- 기존 YouTube 플레이어를 재생성하지 않고 `#pl-stage` 안에 유지한다.
- Fullscreen API가 가능하면 `#pl-stage` 자체를 전체화면으로 열고, 거부되거나 미지원이면 `.fullscreen-fallback` CSS 확장 모드를 사용한다.
- 문제 `#overlay`, 순위 `#board-overlay`, 이동 가능한 `#pl-qr-bubble`을 모두 `#pl-stage` 자식으로 두어 영상과 같은 전체화면 계층을 공유한다.
- QR 좌표 보정은 `teacher-stage.js`의 `clampBubblePosition()` 순수 함수에 분리했으며 Pointer Events 하나로 마우스와 터치를 처리한다.

주요 함수:

- `plEnterStageFullscreen()`, `plExitStageFullscreen()`, `plHandleFullscreenChange()`: 전체화면 진입·해제와 CSS fallback 상태를 관리한다.
- `plGoHomeFromStage()`, `plEndSession()`: 홈/전체화면 해제와 실제 세션 종료를 분리한다.
- `plRenderOverlay()`, `plCloseQuestion()`: stage 안에서 문제를 표시하고 같은 플레이어로 계속 재생한다.
- `plToggleQrBubble()`, `plRenderQrBubble()`, `plStartQrDrag()`, `plMoveQrDrag()`, `plEndQrDrag()`, `plClampQrBubble()`: QR 표시·참여 수 갱신·드래그 경계 처리를 담당한다.

로컬 브라우저 검증 결과(2026-08-18):

- 인앱 브라우저를 다시 연결할 수 없어 사용자 승인으로 Chrome을 사용했다. 교사 세션 1개에 실제 학생 5명(`회귀학생1`~`회귀학생5`)을 입장시켜 참여 5명을 확인했다.
- Chrome의 Fullscreen API 요청은 거부되어 `.fullscreen-fallback` 화면 확장 모드로 검증했다. 도구 모음, QR 코드·참여 주소·참여 5명 표시, 실제 마우스 드래그와 stage 경계 유지, stage 내부 문제·순위 오버레이를 확인했다.
- 첫 문항에서 `참여 5명 · 제출 1명 · 미제출 4명`을 확인한 뒤 타이머 마감 자동 제출로 `제출 5명 · 미제출 0명`이 되었고, 정답 3명·오답 2명(정답률 60%)의 정답 공개와 순위를 확인했다. 대시보드도 참여 학생 5명, 제출 응답 5, 전체 정답률 60%를 표시했다.
- 영상 위치가 `0:01`→`0:12`→`0:24`로 진행되는 동안 QR을 열고 이동했으며, `계속 재생` 전후 같은 iframe URL과 CSS 전체화면 상태가 유지됐다. 문제 타이머 중 QR 열기·닫기·다시 열기도 타이머를 초기화하지 않았다.
- 별도 최소 세션 `2V7AU3HLQ4ZJ`(반 코드 `UTBN6G`)에서 홈 확인 승인 뒤 일반 교사 화면으로 돌아와 참여 1명, 제출 응답 1건, 같은 YouTube iframe URL과 재생 위치 `0:10`이 보존됨을 확인했다. 전체화면 진행 모드에 다시 진입해도 같은 세션·참여 수·iframe이 유지됐다.
- 이후 일반 교사 화면의 `진행 종료`와 확인 대화상자를 승인해 `#/live/2V7AU3HLQ4ZJ`로 이동했고, `종료됨`, 참여 학생 1, 제출 응답 1, 전체 정답률 100%, `1-1-6 홈종료학생` 응답 보존과 `진행을 종료했습니다` 알림을 확인했다.
- 콘솔 재검증은 새 교사 탭을 만든 시점부터 같은 탭 하나를 계속 측정했다. 새 세션 `3NQP8V67QYT7`(반 코드 `RFGQK2`) 생성, 실제 학생 5명 입장, CSS 전체화면, 영상 재생, QR 열기·닫기, 문항 공개·종료, 계속 재생, 전체화면 재진입까지 Firestore/WebChannel 경고는 0건이었다. 같은 탭에는 `2026-08-18T01:00:27.909Z`와 `.910Z`에 YouTube iframe의 광고 차단 대응 요청이 Chrome 확장 프로그램 `chrome-extension://ebifonbnmhogaadkpjfhbgphocgkbaod/.../ublock-filters.js`에서 실패한 오류 2건이 기록됐다. 이는 애플리케이션 또는 Firebase 소스가 아니므로 코드나 로깅을 변경하지 않았다.
- 홈 확인 대화상자 뒤 Chrome 제어가 30초 후 재시작되는 현상이 다시 발생했다. 재연결한 같은 물리 탭의 `dev.logs()`가 빈 배열을 반환해 이 수집기는 제어 연결을 넘겨 로그 이력을 보존하지 않는다는 점도 확인했다. 따라서 이전 장기 실행 탭의 Firestore WebChannel 경고 3건과 별도 새 탭의 0건을 합쳐 콘솔 0건으로 판정할 수 없으며, 홈·종료까지 하나의 연속 로그로 증명하려면 대화상자 제어가 안정적인 깨끗한 Chrome 프로필 또는 DevTools의 영구 로그 보존으로 다시 검증해야 한다. 터치 포인터 경로는 자동 회귀 테스트로 확인했다.
- 광고 차단기를 껐다는 사용자 확인 뒤 Fix Round 5에서 새 Chrome 교사 탭 `1242090908`로 다시 측정했다. 첫 세션 `Z2C6DY2KVL6N`(반 코드 `4WK2TK`)은 학생 5명과 `1920×911` CSS fallback 전체화면까지 확인했으나 YouTube API가 플레이어 iframe을 만들지 않아 같은 탭을 새로고침했고, 이 앱의 교사 세션은 URL로 복구되지 않으므로 정상 종료 UI에 다시 접근하지 못했다.

## 8. 다중 영상 플레이리스트

편집기와 저장 형식:

- 세트는 하나 이상의 영상 카드로 구성한다. 카드에서 영상 추가, 위·아래 순서 이동, 영상과 소속 문항 함께 복사, 확인 후 삭제, 미리보기 선택을 할 수 있다. 마지막 영상 한 개는 삭제하지 못한다.
- 각 영상은 `분:초` 직접 입력과 시작·종료 슬라이더를 함께 제공한다. 문항 시각은 그 영상의 시작·종료 구간 안에 있어야 하며, 직접 입력하거나 문항 타임라인의 번호 마커를 드래그해 조정한다.
- 문항 타임라인의 0~100%는 전체 YouTube 길이가 아니라 해당 영상의 설정된 시작·종료 구간이다. 문항 번호는 영상별로 다시 시작하지 않고 플레이리스트 전체에서 연속된다.
- Firestore 세트 문서는 `videos[]`를 표준으로 저장한다. 문항 이미지 키는 `v{videoIndex}q{questionIndex}`이며, 위의 단일 영상·숫자 이미지 키 호환 경로를 유지한다.
- 세트 구조와 이미지 교체는 하나의 Firestore batch로 커밋한다. 저장 실패 시 새 구조만 먼저 공개되는 부분 저장을 만들지 않으며, 가져오기와 복제도 같은 원자 저장 경로를 쓴다.

교사 진행 동작:

- 현재 영상의 시작·종료 구간으로 계산한 타임라인에 현재 영상 문항만 표시하되 전체 문항 번호를 쓴다. 진행 막대와 마커는 동일한 구간 계산을 사용한다.
- 16:9 플레이어는 일반 화면과 Fullscreen API 또는 CSS fallback 전체화면에서 중앙에 맞춘다. 문제·정답·순위와 이동 가능한 QR은 모두 같은 `#pl-stage` 안에 있어 영상과 동일한 전체화면 계층을 공유한다.
- 문제를 닫고 계속 재생할 때 YouTube iframe을 새로 만들지 않는다. 영상의 종료 시각에 도달하면 열린 문제 처리를 마친 뒤 3초 안내를 보여 주고 다음 영상의 시작 시각부터 재생한다.
- 마지막 영상이 끝나면 완료 메뉴에서 순위, 대시보드, 처음부터 다시 보기, 진행 종료를 선택한다. 완료 화면 자체는 세션을 종료하지 않으며 명시적으로 `진행 종료`를 눌러야 학생 세션이 끝난다.
- 세션 시작 시 세트 구조와 문항 이미지를 세션 하위 snapshot에 고정한다. 학생·대시보드·관리자 조회는 snapshot을 우선하고, 이전 세션만 현재 세트로 fallback하므로 시작 뒤 세트를 편집하거나 재정렬해도 이미 시작한 수업의 문항 번호와 이미지가 바뀌지 않는다.
- 같은 시각의 여러 문항이나 다른 문항이 열린 동안 지난 문항은 queue에 남겨 순서대로 연다. 설정 종료가 실제 YouTube 길이보다 길면 실제 길이를 종료로 사용하고, 실제 `ENDED` 이벤트도 종단 신호로 처리한다.

주요 함수와 책임:

- `PlaylistCore.normalizeVideos(raw)`: 신형 `videos[]`와 구형 최상위 단일 영상 필드를 같은 영상 배열 모델로 정규화한다.
- `PlaylistCore.flattenQuestions(videos)`: 영상별 문항을 전역 순서로 평탄화하고 canonical 이미지 키, 전체 번호, 영상·문항 인덱스를 붙인다.
- `mkTimelineDomain(video)`: 편집기의 직접 입력·슬라이더·문항 마커가 공유할 시작·종료·최대 구간을 계산한다.
- `mkSetRange(videoIndex, edge, value)`: 편집기 시작·종료 값을 1초 이상 간격과 알려진 영상 길이 안으로 보정하고 UI를 갱신한다.
- `mkSetQuestionTime(videoIndex, questionIndex, value)`: 문항 시각을 해당 영상 구간 안으로 보정하고 입력 칸과 타임라인 마커를 동기화한다.
- `plLoadVideo(index, autoplay)`: 기존 YouTube 플레이어에 목표 영상과 시작 시각을 로드하고, 이전 영상의 지연 이벤트를 구분할 세대·기대 ID 상태를 초기화한다.
- `plAdvanceVideo()`: 다음 영상이 있으면 `plLoadVideo()`로 넘기고, 없으면 `plCompletePlaylist()`로 완료 상태에 진입한다.
- `plCompletePlaylist()`: 플레이어를 멈추고 완료 메뉴를 표시하되 Firestore 세션은 종료하지 않는다.
- `plReplayPlaylist()`: 참여·응답은 유지하고 문항 발화 상태를 초기화한 뒤 첫 영상을 다시 로드한다.
- `plRenderTimeline(force)`: 현재 영상의 재생 구간을 기준으로 진행 막대와 전역 번호 문항 마커·상태·다음 문항 안내를 렌더링한다.

## 11. 아직 남아 있는 주의점

- 승인된 교사는 공유 수업·사본 생성을 위해 다른 승인 교사의 세트 원본, 정답·해설·이미지를 읽을 수 있다. 학생과 미승인 사용자는 읽지 못한다.
- 프로덕션 이전은 아직 실행하지 않았고 엄격한 규칙 배포 게이트는 닫혀 있다. 실제 dry-run/apply 감사 보고서가 `safeToDeployStrictRules: true`임을 증명하기 전에는 규칙이나 사이트를 공개 배포하면 안 된다.
- 로컬 초안은 기기별 브라우저 저장소이므로 다른 컴퓨터와 동기화되지 않는다. 다른 컴퓨터에서 이어서 작업하려면 Firestore에 정식 저장해야 한다.
- Firebase 사용량과 Firestore 읽기·쓰기 비용은 Firebase Console에서 정기적으로 확인한다.
- 기존 Realtime Database 원본은 충분한 백업과 운영 검증이 끝나기 전까지 삭제하지 않는 편이 안전하다.
