# 퀴즈 저장·제출·동기화 타이머 설계

## 목표

퀴즈 편집 중 실수로 내용을 잃지 않게 하고, 학생이 답을 검토한 뒤 제출하거나 제한시간 종료 시 자동 제출되게 한다. 교사는 각 문항의 참여·제출·미제출 인원과 남은 시간을 즉시 확인한다. 교사와 학생 화면의 타이머는 같은 Firestore 서버 시각을 기준으로 표시한다.

## 1. 퀴즈 편집 저장

- 기존 저장 버튼은 Firestore 정식 저장 기능으로 유지한다.
- Windows/Linux의 `Ctrl+S`와 macOS의 `Cmd+S`는 브라우저의 페이지 저장을 막고 기존 저장 동작을 실행한다.
- 텍스트·선택지·설정·문항 구조·이미지가 변경되면 현재 브라우저의 로컬 저장소에 임시 초안을 기록한다. 짧은 디바운스를 적용해 매 키 입력마다 직렬화하지 않는다.
- 임시 초안 키는 새 세트와 기존 세트를 구분하고, 기존 세트는 세트 ID별로 분리한다.
- Firestore 정식 저장에 성공하면 해당 임시 초안을 삭제하고 `저장됨 · HH:MM`을 표시한다.
- 저장 중에는 중복 저장을 합치고 `저장 중…`을 표시한다. 실패하면 초안을 유지하고 `저장 실패 · 다시 시도`를 표시한다.
- 편집 화면 진입 시 서버 데이터보다 새로운 임시 초안이 있으면 복구 여부를 묻는다. 사용자가 거절하면 초안을 삭제하고 서버 데이터를 사용한다.
- 다른 컴퓨터에서는 마지막으로 Firestore에 정식 저장한 상태부터 이어서 편집한다. 임시 초안은 기기 간 동기화하지 않는다.

## 2. 학생 응답 상태

각 문항의 학생 화면 상태를 다음처럼 구분한다.

```text
미선택 → 선택 중 → 제출됨
             ↑       ↓
             └─ 다시 고르기

선택 중 + 시간 종료 → 자동 제출
미선택 + 시간 종료 → 미제출
```

- 객관식과 O/X는 한 답을 선택하며, 번호를 누르는 것만으로는 제출하지 않는다.
- 복수정답은 여러 답을 선택한 뒤 제출한다.
- 단답형과 서술형은 입력한 텍스트를 제출한다.
- `제출하기`는 현재 답을 해당 학생의 응답 문서에 확정한다.
- 제출 후 제한시간이 남아 있으면 `다시 고르기`를 누를 수 있다. 이때 제출 확정을 해제하고 이전 답을 선택·입력 상태로 복원한다.
- 다시 고른 뒤 재제출할 수 있다. 제한시간 종료 순간에는 그때 화면에 있는 최신 선택·입력 내용을 자동 제출한다.
- 제출 후 다시 고르지 않은 학생의 답은 타이머 종료 때 중복 저장하지 않는다.
- 공백뿐인 단답형·서술형은 답이 없는 것으로 보고 자동 제출하지 않는다.
- 정답 공개 또는 문항 종료 뒤에는 제출 취소와 답 변경을 허용하지 않는다.

## 3. 동시성 및 데이터 일관성

- 학생 응답 문서의 문항별 필드에는 답, 제출 여부와 서버 기준 갱신 시각을 함께 기록한다.
- `다시 고르기`는 해당 문항의 제출 상태를 해제하되 다른 문항의 응답을 보존한다.
- 수동 제출과 타이머 자동 제출이 겹치면 같은 최신 답에 대한 멱등 저장으로 처리한다. 늦게 도착한 오래된 상태가 최신 제출을 덮어쓰지 않게 문항 상태와 마감 시각을 확인한다.
- 자동 제출은 클라이언트 표시 타이머가 아니라 기존 Firestore 서버 시각 보정값과 `openedAt`, 제한시간으로 결정한다.
- 네트워크 오류 시 제한시간 전에는 재시도 안내를 표시한다. 마감 직전 자동 제출이 실패하면 로컬에 마지막 답을 보존하고 재연결 즉시 서버 마감 규칙이 허용하는 범위에서 한 번 재시도한다.

## 4. 교사 화면

- 문항 진행 중 상단에 `참여 30명 · 제출 18명 · 미제출 12명`을 표시한다.
- 참여 인원은 현재 세션의 등록 학생 수, 제출 인원은 현재 문항에 확정 제출한 학생 수, 미제출 인원은 참여 인원에서 제출 인원을 뺀 값이다.
- 학생이 문항 도중 입장하면 참여와 미제출 인원이 증가한다.
- 학생이 제출하면 제출 인원이 증가하고, `다시 고르기`를 누르면 즉시 감소한다.
- 정답 공개 전에는 제출 숫자만 보여주고 정답 및 보기별 응답 분포는 숨긴다.
- 미제출 학생 이름은 교실 화면의 개인정보 노출을 피하기 위해 표시하지 않는다.

## 5. 동기화 타이머 UI

- 교사와 학생 화면에 같은 가로 진행 막대와 큰 남은 시간 숫자를 표시한다.
- 막대는 남은 시간 비율만큼 연속적으로 줄고, 숫자는 매초 갱신한다.
- 기본 색상은 초록색, 7초 이하는 주황색, 3초 이하는 빨간색이다. 색상만으로 상태를 전달하지 않고 숫자를 항상 함께 표시한다.
- 두 화면은 같은 서버 기준 마감 시각을 사용하며 표시 차이는 1초 이내여야 한다.
- 브라우저가 `prefers-reduced-motion`을 요청하면 연속 애니메이션을 줄이고 숫자 및 단계형 막대만 갱신한다.
- 0초가 되면 학생 입력을 잠그고 자동 제출 또는 미제출 처리를 한 뒤 공개 정책에 따른 다음 상태로 전환한다.

## 6. 오류 및 경계 조건

- 제출할 답이 없으면 `답을 선택하세요` 또는 `답을 입력하세요`를 표시하고 수동 제출하지 않는다.
- 저장·제출 요청 중 버튼을 반복해서 눌러도 중복 요청을 만들지 않는다.
- 이미 공개된 문항, 종료된 세션, 잘못된 학생 식별자로 온 변경 요청은 거부한다.
- 탭이 백그라운드에 있다가 돌아와도 누적된 interval 횟수가 아니라 서버 마감 시각으로 남은 시간을 다시 계산한다.
- 학생이 여러 탭을 열었을 때 마지막으로 서버가 승인한 최신 상태를 표시하고, 다른 탭의 제출·취소도 실시간으로 반영한다.

## 7. 검증 기준

- `Ctrl+S`/`Cmd+S`, 저장 버튼, 저장 상태 표시와 로컬 초안 생성·복구·삭제를 자동 테스트한다.
- 다섯 문항 유형에서 선택·입력만으로 제출되지 않고, 버튼 제출과 다시 고르기가 정확히 상태를 바꾸는지 테스트한다.
- 미제출 상태에서 마감되면 최신 답이 자동 제출되고, 빈 답은 미제출로 남는지 테스트한다.
- 수동 제출과 자동 제출 경합, 중복 클릭, 네트워크 실패 후 재시도를 테스트한다.
- 학생 입장·제출·다시 고르기에 따라 참여·제출·미제출 수가 실시간으로 변하는지 테스트한다.
- fake timer와 서버 시각 보정값으로 교사·학생의 막대 및 숫자가 동일하게 변하고 7초·3초 색상 경계를 지키는지 테스트한다.
- 실제 브라우저에서 편집 초안 복구와 교사·학생 두 창의 제출·취소·자동 제출·타이머 동기화를 회귀 검증한다.

## 제외 범위

- 사용자 계정 기반 기기 간 초안 동기화
- 미제출 학생 이름 공개
- 이미 종료되거나 공개된 문항의 답 수정
- 타이머 효과음 및 진동
