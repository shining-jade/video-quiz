# 비로그인 영상 퀴즈 진행 링크 설계

## 1. 목적

운영자가 만든 영상 퀴즈를 여러 교사가 계정, 로그인, 관리자 승인 또는 공유 비밀번호 없이 각 반에서 실행할 수 있게 한다. 공유 링크를 받은 각 교사가 수업을 시작할 때마다 독립된 세션과 6자리 반 코드를 발급하며, 학생·응답·점수·대시보드 데이터가 다른 실행과 섞이지 않아야 한다.

공유 링크는 공개 자료 주소가 아니라 링크 자체가 진행 권한을 나타내는 비밀 URL이다. 원본 세트의 편집 권한이나 운영자 계정 권한은 부여하지 않는다.

## 2. 범위와 비범위

### 포함

- 세트 소유자가 비로그인 진행 링크를 생성, 재복사, 해제 및 재발급하는 흐름
- 공유 링크 전용 최소 데이터 projection과 버전 관리
- 보이지 않는 Firebase 익명 인증을 통한 진행자별 세션 소유권
- 같은 링크를 여러 브라우저에서 동시에 실행하는 흐름
- 세션별 반 코드, 학생, 응답, 채점 및 대시보드 분리
- 원본 소유자와 관리자의 파생 세션 열람
- 링크 해제, 잘못된 링크, 네트워크 실패 및 중복 시작 처리
- Firestore Rules, 저장소 계층, UI 및 회귀 테스트

### 제외

- 비로그인 사용자의 세트 편집, 복제, 파일 내보내기 또는 공동 편집
- 비로그인 진행자의 기기 간 세션 인계나 계정 복구
- 공유 링크별 비밀번호 또는 추가 PIN
- 공개 자료실 게시를 공유 링크의 선행 조건으로 만드는 것
- 이미 종료된 비로그인 세션을 익명 진행자가 다른 기기에서 복구하는 것

## 3. 사용자 흐름

### 3.1 운영자

1. 소유한 활성 세트의 `비로그인 진행 링크`를 누른다.
2. 활성 공유가 없으면 새 공유 ID와 비밀 토큰을 만들고 현재 세트 revision의 실행용 projection을 게시한다.
3. 활성 공유가 있으면 동일한 링크를 다시 복사한다.
4. 원본을 수정하면 같은 공유 링크의 projection을 새 revision으로 갱신한다.
5. `공유 링크 해제`를 누르면 신규 실행을 즉시 차단한다.
6. 다시 공유하면 이전 토큰을 되살리지 않고 새 공유 ID와 새 토큰을 발급한다.
7. 운영자는 원본 세트에서 파생된 모든 세션과 응답을 확인할 수 있다.

공유 생성·갱신·해제는 원본 소유자 또는 관리자만 수행한다. 공동 편집자에게는 기본적으로 공유 수명주기 관리 권한을 주지 않는다.

### 3.2 비로그인 진행자

1. `#/guest-play/{shareId}?token={secret}` 형태의 링크를 연다.
2. 앱은 로그인 UI를 표시하지 않고 Firebase 익명 사용자를 준비한다.
3. 유효한 활성 공유이면 제목, 영상 수, 문항 수, 진행 설정, 문항 미리보기와 반 이름 입력란을 보여준다.
4. `우리 반 시작하기`를 누르면 현재 익명 UID 소유의 새 세션과 새 6자리 반 코드를 원자적으로 할당한다.
5. 기존 진행 화면을 사용해 학생 참여 링크·QR, 문제 진행, 채점 및 자기 세션의 대시보드를 조작한다.

같은 공유 링크를 다른 브라우저가 열면 별도 익명 UID를 갖는다. 각 브라우저는 자신이 만든 세션만 읽고 변경할 수 있다.

### 3.3 학생

학생 흐름은 기존 `#/join/{code}`를 유지한다. 학생도 보이지 않는 익명 인증을 사용하며, 세션 ID 아래에서만 참여·응답한다. 진행자 공유 링크를 학생에게 직접 배포하지 않도록 진행 화면에서 학생 참여 링크와 QR을 명확히 구분한다.

## 4. 데이터 모델

다음 컬렉션과 하위 컬렉션 이름을 사용한다.

### 4.1 공유 메타데이터

`guest_quiz_shares/{shareId}`는 다음 필드만 가진다.

- `shareId`
- `sourceSetId`
- `sourceOwnerUid`
- `status`: `active | revoked`
- `tokenHash`
- `revision`
- `createdAt`, `updatedAt`, `revokedAt`

클라이언트 URL의 비밀 토큰 원문은 Firestore에 저장하지 않는다. 동일한 canonical 직렬화와 해시 알고리즘을 사용해 검증한다. 토큰은 일반적인 세트 ID나 6자리 반 코드와 달리 온라인 추측이 현실적으로 불가능한 길이의 암호학적 난수여야 한다.

### 4.2 실행용 projection

`guest_quiz_shares/{shareId}/revisions/{revision}`와 그 아래 `videos`, `questions`, `images` 하위 컬렉션에 다음 실행 필드만 저장한다.

- 제목과 비식별 표시 정보
- 정규화된 영상 URL/ID 및 시작·종료 구간
- 문항 유형, 시각, 본문, 선택지, 정답, 복수 정답/허용 답안
- 문제·해설 이미지의 실행용 데이터
- 해설
- 제한 시간, 공개 방식, 자동 일시정지 등 진행 설정
- `shareId`, `revision`, schema version

다음 정보는 금지한다.

- 소유자 이메일 또는 인증 provider 정보
- 공동 편집자와 승인 목록
- 소유자 UID를 UI에 노출하는 필드
- 기존 학생, 세션, 응답 및 채점 데이터
- 휴지통, 삭제, moderation, 내부 감사 또는 관리용 필드

projection 생성은 허용 필드 목록 방식으로 구현하며, 금지 필드 제거 방식에 의존하지 않는다.

### 4.3 세션

비로그인 실행 세션은 기존 세션 계약을 최대한 재사용하고 다음 provenance를 추가한다.

- `teacherUid`: 세션을 시작한 익명 UID
- `sessionActorType`: `guest`
- `sourceShareId`
- `sourceSetId`
- `sourceRevision`
- `sourceOwnerUid`: 원본 소유자의 감사·조회용 식별자
- 새 `code`, 반 이름, 상태 및 기존 세션 필드

세션 시작 시 필요한 퀴즈 데이터는 시작 revision으로 고정한다. 원본이나 공유 projection이 갱신되어도 진행 중 세션의 문항·정답·채점 기준은 바뀌지 않는다.

## 5. 인증과 권한

“비로그인”은 사용자에게 계정 입력이나 로그인 화면을 요구하지 않는다는 뜻이다. Firestore의 세션별 소유권을 안전하게 적용하기 위해 앱 내부에서는 Firebase Anonymous Authentication을 사용한다.

- 공유 링크 읽기: callable backend가 활성 share와 올바른 비밀 토큰을 검증한 뒤, 현재 익명 UID와 `shareId`, `revision`, 제한된 만료 시간을 묶은 Firebase custom token을 발급한다. 클라이언트는 이 token으로 다시 인증한 뒤 projection을 읽는다.
- 세션 생성: 검증된 활성 share의 현재 revision에서만 가능하며 `teacherUid == request.auth.uid`여야 한다.
- 진행자 조작: 해당 세션의 `teacherUid`와 일치하는 익명 UID만 가능하다.
- 다른 익명 진행자: 세션 목록 조회, 읽기, 변경 및 응답 열람을 모두 금지한다.
- 원본 소유자: `sourceOwnerUid`가 자신의 승인된 교사 UID인 파생 세션을 읽을 수 있다.
- 관리자: 기존 관리자 정책에 따라 파생 세션을 읽고 운영할 수 있다.
- 학생: 기존 세션 코드 lookup과 학생 전용 규칙만 사용하며 진행자 권한을 얻지 않는다.

비밀 토큰을 단순히 URL에서 읽어 Firestore Rules가 임의 query로 비교하게 만들지 않는다. 토큰 검증과 capability 발급은 최소 권한 callable backend 한 곳에서만 수행한다. Rules는 서명된 `guestShareId`, `guestShareRevision`, `guestCapabilityExpiresAt` claim과 고정 문서 경로를 검증한다. backend와 Rules 어느 쪽에서도 private 원본 읽기 정책을 완화하지 않는다.

## 6. 동시성과 세션 격리

기존 반 코드 예약, allocation token, heartbeat 및 활성화 transaction을 재사용한다. 공유 링크를 동시에 여러 번 누르거나 네트워크 응답이 재전송되어도 한 시작 시도는 최대 한 세션만 활성화해야 한다.

- 세션 ID와 반 코드는 실행마다 새로 발급한다.
- 학생, 응답, 채점은 세션 ID 하위 경로에만 저장한다.
- 진행자 heartbeat와 대시보드는 세션 소유 익명 UID에 묶는다.
- 동일 `sourceShareId`는 조회·감사 provenance일 뿐 데이터 격리 키로 사용하지 않는다.
- 한 링크의 동시 실행 수 때문에 서로의 진행 상태가 변경되어서는 안 된다.

## 7. 공유 수명주기와 revision

### 생성

소유권, 세트 활성 상태, projection 유효성 및 현재 content revision을 transaction에서 다시 확인한 뒤 share를 활성화한다. 부분 projection이 외부에 보이는 상태를 허용하지 않는다.

### 원본 수정

활성 공유가 있는 원본을 저장하면 새 projection을 완성한 뒤 share의 현재 revision 포인터를 전환한다. 새 세션은 새 revision을 사용하고 기존 세션은 고정된 시작 revision을 유지한다. 갱신 실패 시 이전 완전한 revision을 계속 제공하고 운영자에게 재시도를 안내한다.

### 해제

share 상태를 `revoked`로 변경해 신규 preview와 세션 생성을 차단한다. 이미 `live`인 세션은 진행자가 정상 종료할 수 있도록 최소 권한을 유지한다. 해제 이후 종료된 세션의 재개나 새 세션 파생은 허용하지 않는다.

### 재발급

해제된 share 또는 토큰을 다시 활성화하지 않는다. 새 share ID, 새 비밀 토큰, 현재 revision projection을 발급한다. 이전 링크는 영구적으로 사용할 수 없어야 한다.

## 8. 화면 설계

### 세트 목록

- 기존 `🔗 링크`를 `🔗 비로그인 진행 링크`로 변경한다.
- 활성 공유가 없으면 생성 후 복사하고, 있으면 기존 링크를 복사한다.
- 소유자에게만 `공유 링크 해제`를 제공한다.
- 공유 상태 확인 실패 시 링크를 임의로 재발급하지 않고 `상태 다시 확인`을 제공한다.

### 비로그인 preview

- 앱 상단에 “공유받은 퀴즈 진행”임을 표시한다.
- 편집, 복제, 파일, 공개 자료실, 세트 목록 및 관리자 기능을 노출하지 않는다.
- 제목, 영상/문항 수, 진행 설정, 문항 미리보기, 선택적 반 이름과 `우리 반 시작하기`만 제공한다.
- 정답 표시는 진행자에게 필요한 현재 preview 정책을 유지하되, 링크가 학생에게 전달되지 않도록 경고 문구를 둔다.

### 진행 화면

기존 진행 화면, 전체화면, 학생 QR, 문제 전환, 공개, 채점 및 대시보드를 재사용한다. 로그인 사용자 메뉴 대신 `공유 퀴즈 진행 중` 상태를 보여주며 세트 편집으로 이동하는 링크는 제거한다.

## 9. 오류 처리

- 잘못되거나 해제된 링크: “사용할 수 없는 진행 링크입니다. 만든 분에게 새 링크를 요청해 주세요.”
- 익명 인증 실패: 로그인 창을 열지 않고 네트워크 확인과 재시도 제공
- projection 갱신 실패: 이전 완전 revision 유지, 운영자에게 실패 상태와 재시도 제공
- 세션 할당 실패: 예약을 정리하거나 기존 pending 할당을 복구한 후 재시도
- 중복 시작: 버튼 잠금과 idempotent allocation으로 중복 활성 세션 방지
- 원본 휴지통·삭제·소유자 중지: 신규 공유와 신규 세션을 fail closed로 차단하고 활성 세션은 안전 종료 정책 적용

오류 메시지에는 토큰, UID, 이메일, 내부 문서 경로를 포함하지 않는다.

## 10. 개인정보와 운영상 제한

공유 링크는 전달받은 사람이 다시 전달할 수 있는 bearer credential이다. 비밀번호를 요구하지 않는다는 제품 결정을 유지하되 다음 완화책을 적용한다.

- 긴 난수 토큰과 안전한 해시 비교
- 검색, 공개 자료실, 목록 query 및 로그에 토큰 미노출
- 운영자의 즉시 해제와 새 토큰 재발급
- projection 최소화와 원본 데이터 직접 읽기 금지
- 세션별 익명 UID 소유권

브라우저 저장소를 삭제하거나 다른 기기로 이동하면 비로그인 진행자는 기존 세션 제어권을 복구할 수 없다. 원본 운영자와 관리자는 provenance를 통해 계속 조회할 수 있다. 이 제한은 화면에서 수업 시작 전에 간단히 안내한다.

## 11. 테스트 및 수용 기준

### 단위 테스트

- 토큰 생성·canonical hashing·검증과 민감 값 비노출
- 허용 목록 projection 및 금지 필드 거부
- share 생성, 갱신, 해제, 재발급 상태 전이
- revision 고정과 신규 세션의 최신 revision 선택
- guest route와 교사 route 분리

### Firestore Rules 및 emulator 테스트

- 유효한 익명 진행자의 활성 share preview와 세션 생성 허용
- 잘못된 토큰, 해제 share, 비인증 요청 및 오래된 revision 거부
- 한 익명 진행자가 다른 진행자의 세션·응답을 읽거나 변경하지 못함
- 원본 소유자와 관리자의 파생 세션 조회 허용
- 학생이 진행자 권한이나 실행용 전체 projection을 얻지 못함
- 원본 private `quiz_sets` 접근 정책이 완화되지 않음

### 통합·브라우저 테스트

- 새 비로그인 브라우저에서 로그인 UI 없이 preview 및 수업 시작
- 동일 링크를 두 브라우저에서 동시에 실행해 서로 다른 세션과 반 코드 발급
- 두 세션의 학생, 응답, 점수, 진행 상태 및 대시보드 완전 분리
- 새로고침 후 같은 브라우저가 자신의 활성 세션을 계속 제어
- 공유 해제 후 신규 실행 차단과 기존 live 세션 정상 종료
- 원본 수정 후 새 세션만 최신 revision 사용
- 기존 승인 교사 진행, 학생 참여, 공개 자료실, 공동 편집 및 휴지통 회귀 없음

## 12. 배포와 마이그레이션 원칙

기존 `#/play/{setId}` 링크를 비로그인으로 개방하지 않는다. 새 guest route와 새 데이터 경계를 별도로 배포한다. Firestore Rules와 필요한 index/backend가 먼저 안전하게 준비되고 검증된 뒤 정적 앱에서 링크 생성 UI를 활성화한다.

기존에 복사된 `#/play/{setId}` 링크는 계속 승인 교사 전용으로 동작한다. 운영자가 새 버튼을 눌러 생성한 링크만 비로그인 진행 권한을 가진다. 롤백 시 신규 share 생성을 중단하되 기존 원본 세트, 수업 세션, 학생 및 응답 데이터는 삭제하지 않는다.
