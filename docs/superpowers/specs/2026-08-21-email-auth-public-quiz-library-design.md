# 이메일 로그인과 공개 퀴즈 자료실 설계

> 운영 주의(2026-08-22): 이 문서는 역사적 설계/구현 기록이다. 아래의 개별 rollout·deploy 순서는 폐기되었고, production 전체 순서는 오직 [`docs/RELEASE-RUNBOOK.md`](../../RELEASE-RUNBOOK.md)의 R0~R15를 따른다.


## 목표

기존 Google 교사 로그인을 유지하면서 Firebase Authentication의 이메일·비밀번호 가입과 비밀번호 재설정을 추가한다. 두 로그인 방식 모두 이메일 신뢰성과 관리자 승인을 통과한 뒤에만 교사 기능을 사용할 수 있다.

승인된 교사가 자기 세트를 명시적으로 공개하면 다른 승인 교사가 공개 자료실에서 검색·미리보기하고 독립 사본을 만들 수 있게 한다. 원본 편집 권한, 계정 개인정보, 학생 응답과 수업 기록은 공개하거나 복사하지 않는다.

## 범위

### 포함

- Google 로그인 유지
- 이메일·비밀번호 가입, 이메일 인증, 로그인, 로그아웃, 비밀번호 재설정
- 인증 완료 후 한 번의 교사 권한 신청과 기존 관리자 승인 절차
- 이메일 계정에 대한 승인·정지·탈퇴 대기·삭제 정책
- 소유자 전용 공개 게시·철회
- 승인 교사 전용 공개 자료실 검색·미리보기·사본 생성
- 관리자 공개 중지
- 공개 세트 출처 표시
- Firestore Rules, Emulator 테스트, 브라우저 인수 검증과 배포 절차

### 제외

- 이메일과 무관한 별도 사용자명 로그인
- 관리자가 사용자의 비밀번호를 조회하거나 설정하는 기능
- 익명 방문자나 학생에게 공개 자료실을 노출하는 기능
- 공개 원본의 공동 편집
- 이미 생성된 사본을 원본과 자동 동기화하는 기능
- 유료 결제, 사용량 보장 또는 콘텐츠 추천 알고리즘

## 핵심 원칙

1. 인증, 교사 승인, 세트 공개는 서로 독립된 권한 단계다.
2. 이메일 인증만으로 교사 권한을 주지 않는다.
3. 공개 자료실은 비공개 원본 문서를 직접 나열하지 않고 최소 필드의 공개 projection을 사용한다.
4. 공개 세트는 읽기 전용이며 다른 교사는 항상 자기 소유 사본을 만든 뒤 편집한다.
5. 비밀번호와 재설정 토큰은 Firebase Authentication만 관리한다.
6. 실패와 경합은 권한 확대보다 중단을 선택한다.

## 인증과 교사 승인

### 로그인 선택

로그인 화면은 다음 동작을 제공한다.

- Google로 계속하기
- 이메일로 가입
- 이메일로 로그인
- 비밀번호를 잊으셨나요?

Google 로그인은 현재 흐름을 유지한다. Google 공급자가 검증한 이메일을 사용하며 로그인 후 교사 권한 신청 단계로 이동한다.

이메일 가입은 이름, 이메일, 비밀번호를 받는다. 이메일은 canonical 소문자로 정규화하고 비밀번호는 최소 8자를 요구한다. 가입 직후 Firebase 인증 메일을 발송한다. 사용자가 인증 링크를 누른 뒤 사이트에서 토큰을 새로 고치고 `emailVerified`를 서버 상태로 다시 확인해야 교사 권한을 신청할 수 있다.

교사 권한 신청은 한 번만 한다. 이메일 인증은 관리자 승인이 아니라 이메일 소유 확인 단계다. 관리자는 기존 신청 관리 화면에서 이름, canonical 이메일과 신청 상태를 보고 승인 또는 거절한다. 승인 이후에만 세트 생성·복사·수업 시작과 공개 자료실 사용이 가능하다.

### 계정 연결 충돌

같은 이메일이 Google 공급자와 이메일·비밀번호 공급자에 걸쳐 나타나더라도 클라이언트가 임의로 교사 권한을 복제하거나 계정을 자동 병합하지 않는다. Firebase가 `account-exists-with-different-credential`과 같은 충돌을 반환하면 기존 로그인 방식으로 먼저 인증하도록 안내한다. 계정 연결은 현재 사용자 재인증을 거치는 별도 명시 동작이 도입되기 전까지 범위 밖으로 둔다.

### 비밀번호 재설정과 개인정보 보호

비밀번호 재설정은 Firebase의 이메일 링크를 사용한다. 계정 존재 여부를 추측할 수 없도록 성공·미등록 이메일 모두 `입력한 이메일을 확인해 주세요`라는 동일한 사용자 메시지를 표시한다. 관리자는 비밀번호 원문, 해시 또는 재설정 링크를 볼 수 없다.

가입, 인증 메일 재발송과 비밀번호 재설정에는 짧은 클라이언트 대기 시간과 Firebase 제한 오류 안내를 둔다. 대량 요청 방지는 Firebase Auth 제한을 기본으로 하고, 필요할 때 App Check를 별도 단계로 도입한다.

## 공개 퀴즈 자료실

### 공개 상태

새 세트와 사본은 항상 비공개다. 소유자만 `공개 자료실에 게시`와 `공개 철회`를 실행할 수 있다. 공동 편집자는 원본 내용을 편집할 수 있어도 공개 상태를 바꿀 수 없다.

세트 상태는 사용자에게 다음처럼 보인다.

- 비공개
- 공개 중
- 관리자 공개 중지

휴지통 이동, purge 시작, 소유자 정지 또는 탈퇴 대기 시 공개 projection을 즉시 검색과 직접 읽기에서 숨긴다. 휴지통에서 복원해도 자동 재공개하지 않고 비공개로 복원한다.

### 공개 projection

비공개 원본은 기존 `quiz_sets/{setId}`와 이미지 하위 문서에 유지한다. 별도 공개 컬렉션은 공개 탐색에 필요한 최소 정보만 가진다. 구체적인 경로와 필드는 구현 계획에서 기존 Firestore 경로·Rules 예산을 확인해 확정하되 다음 정보만 허용한다.

- 공개 ID와 원본 세트 ID의 서버 검증 가능한 연결
- 제목과 짧은 설명
- 제작자 표시명
- 영상 수와 문항 수
- 게시·갱신 시각
- 공개 상태와 revision
- 검색용으로 제한된 정규화 필드

이메일, Firebase UID, 관리자 감사 정보, 공동 편집자, 학생·응답·점수·세션·수업계획 데이터는 공개 projection에 넣지 않는다.

승인된 활성 교사만 공개 목록과 상세 projection을 읽을 수 있다. 미승인 계정, 정지·탈퇴 대기 계정, 학생과 익명 사용자는 목록·직접 get 모두 거부한다.

### 게시와 철회

게시 transaction은 다음을 서버에서 재확인한다.

- 호출자가 현재 세트 소유자다.
- 세트가 active이고 휴지통·purge 상태가 아니다.
- 교사 allowance가 active다.
- 원본 revision과 공개 revision이 일치한다.
- 허용된 공개 필드만 projection에 기록한다.

철회는 원본의 공개 상태와 projection 가시성을 같은 원자 작업으로 바꾼다. 관리자 공개 중지는 관리자 UID allowance와 대상 revision을 재검증하고 감사 시각·행위자를 기록한다. 관리자는 원본 내용을 임의 수정하지 않는다.

### 검색과 미리보기

메인 교사 화면에 `공개 자료실` 메뉴를 추가한다. 승인 교사는 제목, 제작자 표시명, 영상 수, 문항 수를 보고 제한된 검색·페이지 조회를 할 수 있다. Firestore의 query-is-not-a-filter 특성을 지키도록 Rules가 허용하는 정확한 bounded query만 사용한다.

미리보기는 공개 projection과 복사용 공개 콘텐츠 snapshot만 읽는다. 학생 응답과 수업 기록은 어떤 미리보기에도 포함하지 않는다.

### 사본 만들기

`내 세트로 복사`는 공개 상태와 소유자의 활성 allowance를 transaction 시작과 commit 직전에 다시 확인한다. 결과 세트는 다음 조건을 가진 독립 문서다.

- 새 set ID와 현재 교사 소유권
- 비공개 상태
- 공동 편집자 0명
- lifecycle과 이미지 counter의 안전한 초기값
- 문항, 설정, 허용 이미지와 해설 이미지의 완전한 사본
- 원본 공개 ID, 원본 제목과 제작자 표시명으로 구성된 출처 정보

원본 이메일·UID와 관리자 감사 필드는 사본에 들어가지 않는다. 원본이 나중에 수정·철회·삭제되어도 완료된 사본은 유지된다. 복사 도중 실패하면 불완전한 destination을 정상 세트로 노출하지 않으며 같은 요청을 안전하게 재시도할 수 있다.

## UI 흐름

### 가입과 로그인

1. 로그인 선택 화면
2. 이메일 가입 폼
3. 인증 메일 발송 완료 화면
4. `인증 완료 확인`과 `인증 메일 다시 보내기`
5. 인증 완료 뒤 교사 권한 신청 화면
6. 승인 대기·거절·승인 상태 화면

기존 Google 사용자의 동선과 학생 참여 화면은 변경하지 않는다.

### 세트 관리

- 세트 카드에 공개 상태 배지와 소유자 전용 게시·철회 버튼
- 게시 전 공개 정보와 저작권 주의사항 확인창
- 관리자 화면에 공개 세트 중지 목록과 사유 입력
- 공개 자료실에 검색, 상세 미리보기, 내 세트로 복사 버튼
- 사본 상세에 원본 출처 표시

## 오류 처리

- 이메일 미인증, 승인 대기, 정지와 탈퇴 대기는 서로 다른 안내를 표시하되 보호 화면은 모두 즉시 철회한다.
- 인증 상태 변경은 auth generation과 UID를 묶어 오래된 async 결과가 새 사용자의 화면을 복원하지 못하게 한다.
- 게시·철회·복사는 revision/CAS 실패 시 최신 상태를 다시 읽고 명시 재시도를 제공한다.
- 공개 projection과 원본이 불일치하면 fail closed하고 목록에서 숨긴다.
- 네트워크 실패 시 승인, 게시 또는 복사 성공을 추측하지 않고 서버 재조회 후 상태를 결정한다.
- Firebase quota나 일시 오류는 기능을 우회하지 않고 사용자에게 재시도 안내를 제공한다.

## 보안 규칙

- 이메일·비밀번호 계정도 `email_verified`와 공급자·allowance UID/email binding을 서버 규칙에서 확인한다.
- 교사 allowance는 UID 권위 문서를 사용하고 legacy email fallback을 다시 열지 않는다.
- 공개 projection create/update/delete는 소유자 게시 protocol 또는 관리자 중지 protocol의 exact atomic pair만 허용한다.
- 공개 콘텐츠 읽기와 복사는 active 승인 교사만 허용한다.
- 원본, 이미지, 공개 projection의 revision과 content counter 불변식을 유지한다.
- 임의 필드 추가, 소유자 위조, stale 공개, 휴지통 원본 게시와 불완전 사본을 거부한다.

## 데이터 전환과 배포

기존 계정과 세트는 그대로 유지한다. 모든 기존 세트는 공개 필드가 없는 비공개로 취급한다. 공개 projection backfill은 하지 않는다. 이메일 공급자 활성화는 Firebase Console 설정과 승인된 도메인·이메일 템플릿 검토를 포함한다.

배포 순서는 다음 gate를 따른다.

1. Firebase Auth 이메일·비밀번호 공급자와 이메일 템플릿 준비
2. Emulator에서 Auth/Rules/store/UI 전체 검증
3. 호환 Rules 배포
4. 정적 앱 배포
5. Google 기존 관리자, 신규 이메일 교사, 다른 승인 교사로 실제 브라우저 smoke
6. 게시·검색·사본·철회·정지와 비밀번호 재설정 확인

실제 계정 활성화, Rules 배포와 앱 배포는 전체 검증과 독립 보안 리뷰가 통과한 뒤에만 실행한다.

## 테스트 기준

### 단위·통합 테스트

- 이메일 canonicalization, 인증 완료와 미완료 상태
- 가입·로그인·로그아웃·비밀번호 재설정의 정보 비노출 메시지
- Google 로그인 기존 회귀
- auth generation 경쟁과 동일 이메일 공급자 충돌
- 게시·철회·관리자 공개 중지 transaction과 stale revision
- 공개 query 경계와 pagination
- 문항·문항 이미지·해설 이미지가 포함된 사본
- 복사 실패·경합·멱등 재시도
- 휴지통·복원·정지·탈퇴 대기 상태 전환

### Firestore Emulator 보안 행렬

- 소유자, 공동 편집자, 다른 승인 교사, admin, 미승인 계정, 정지 계정, 학생과 익명 사용자
- 공개 목록/get/copy와 비공개 직접 URL
- 원본 소유권·revision·counter·lifecycle forge
- 이메일 인증과 UID/canonical email allowance binding
- 단독 projection 쓰기와 원자 pair 불일치

### 실제 브라우저 인수 기준

- Google 관리자 로그인 회귀
- 이메일 가입→메일 인증→신청→관리자 승인→교사 홈 진입
- 비밀번호 재설정 메일과 재로그인
- 교사 A 게시, 교사 B 검색·미리보기·사본 생성
- A 철회 뒤 새 접근 차단과 B의 기존 사본 유지
- 모바일·넓은 화면 로그인과 공개 자료실 UI
- 앱/Firebase 출처 오류 0

## 성공 조건

- 기존 Google 교사와 학생 수업 흐름이 유지된다.
- 이메일 인증과 관리자 승인 모두 없이는 교사 기능을 사용할 수 없다.
- 관리자가 사용자의 비밀번호나 비밀번호 존재 여부를 알 수 없다.
- 비공개 원본과 개인정보가 공개 자료실 query나 직접 URL에서 노출되지 않는다.
- 공개 세트는 승인 교사만 독립 사본으로 가져올 수 있다.
