# 교사 권한 신청·수업계획·현황판 설계

작성일: 2026-08-20

## 1. 목표

공용 계정을 공유하지 않고 각 교사가 자기 Google 계정으로 권한을 신청하도록 한다. 관리자는 사이트 안에서 신청을 승인·거절·중지하고, 승인된 교사는 수업마다 사용계획을 등록한 뒤 겹침 경고를 확인하고 수업을 진행한다. 메인 화면의 교사용 현황판은 예정·진행 수업과 예상·실제 참여 규모를 보여준다.

동시 수업은 차단하지 않는다. Firestore 무료 할당량은 동시 사용자 수 자체보다 읽기·쓰기 사용량에 영향을 받으므로, 현황판은 계획을 돕는 경고 도구이며 수업 진행의 서버 측 허가 장치가 아니다.

## 2. 사용자와 권한

### 미승인 Google 사용자

- 자신의 권한 신청을 생성하고 상태를 조회하며, 승인 대기 중에는 취소할 수 있다.
- 다른 신청, 교사 목록, 세트, 수업계획과 현황판은 읽을 수 없다.
- 같은 UID로 활성 신청을 중복 생성할 수 없다.

### 승인된 교사

- 기존 퀴즈 제작·복사·수업 진행 권한을 유지한다.
- 수업계획을 만들고 자기 계획을 수정·취소할 수 있다.
- 로그인한 교사용 현황판에서 다른 교사의 수업 시간, 수업명, 예상/실제 참여 인원과 상태만 본다.
- 다른 교사의 이메일, UID, 신청 메모와 관리자 처리 기록은 볼 수 없다.
- 계정 사용 종료를 요청하고 30일 복구 기간 안에 철회할 수 있다.

### 관리자

- 신청자의 이름, 이메일, 소속/메모를 보고 승인·거절한다.
- 승인된 교사를 일시 중지·복구한다.
- 전체 수업계획에서 담당 교사 이름과 이메일을 함께 본다.
- 탈퇴 요청을 처리하고 소유 세트 이전·보존·휴지통 이동을 결정한다.
- 승인·중지·복구·삭제 작업의 최소 감사 기록을 조회한다.

### 학생과 비로그인 사용자

- 교사 신청, 수업계획, 현황판을 읽거나 쓸 수 없다.
- 기존 반 코드 참여 흐름은 변경하지 않는다.

## 3. 교사 권한 신청 흐름

1. 사용자가 Google 로그인한다.
2. 기존 승인 정보가 없으면 `교사 권한 신청` 화면을 표시한다.
3. Google에서 얻은 이름·이메일은 읽기 전용으로 보여주고, 선택 항목인 소속/메모를 입력한다.
4. 신청 문서를 현재 인증 UID로 생성한다.
5. 관리자가 승인하면 기존 승인 교사 문서를 서버 규칙이 요구하는 원자적 쓰기로 만들고 신청 상태를 `approved`로 바꾼다.
6. 거절하면 사유를 선택적으로 남기고 `rejected`로 바꾼다. 재신청은 관리자가 허용한 경우 새 revision으로 가능하다.
7. 승인 직후 해당 사용자는 토큰·서버 승인 상태를 다시 확인한 다음 교사 화면으로 이동한다.

신청 상태는 `pending`, `approved`, `rejected`, `cancelled`만 허용한다. 클라이언트는 자기 신청의 표시용 필드만 쓸 수 있고 상태·처리자·처리 시각은 관리자만 변경한다.

## 4. 교사 사용 중지와 탈퇴

### 일시 중지

- 관리자가 승인 문서의 상태를 `suspended`로 전환하면 새 보호 화면 진입, 편집 저장, 수업 시작을 즉시 차단한다.
- 진행 중 수업은 안전한 종료만 허용하며, 새 문항 열기와 새 학생 참여 허용 여부는 기존 세션 종료 정책과 함께 구현 단계에서 원자적으로 검증한다.
- 복구하면 같은 UID의 소유권과 공동 편집 관계를 유지한다.

### 교사 요청 탈퇴

1. 교사가 `계정 사용 종료 요청`을 누른다.
2. 즉시 권한을 중지하고 `deletionRequestedAt`, `purgeEligibleAt = 요청 시각 + 30일`을 서버 시각으로 기록한다.
3. 30일 동안 교사 또는 관리자가 요청을 철회할 수 있다.
4. 관리자는 완전 삭제 전 소유 세트별로 다음 중 하나를 확정한다.
   - 다른 승인 교사에게 소유권 이전
   - 보존용 관리자 계정으로 이전
   - JSON 백업 확인 후 기존 30일 휴지통 흐름으로 이동
5. 소유 세트가 남아 있거나 진행 중 세션이 있으면 완전 삭제 gate는 닫힌다.
6. gate가 통과하면 앱의 교사 프로필·신청·승인 문서를 삭제 또는 비식별화하고 Firebase Auth 사용자를 관리 작업으로 삭제한다. Google 계정 자체는 삭제하지 않는다.

학생 응답은 교사 탈퇴와 함께 자동 삭제하지 않는다. 별도 개인정보 보존 정책과 기존 세션 정리 절차를 따른다. 감사 기록의 이메일은 보존 기간 후 해시 또는 삭제된 사용자 표기로 치환한다.

## 5. 수업 사용계획

사용계획은 퀴즈 세트가 아니라 실제 반 세션마다 생성한다. 같은 세트를 여러 날짜·반에서 반복 사용하는 경우 각각 별도 계획이 된다.

### 필수 입력

- 수업명 또는 반 이름: 1~80자
- 시작 날짜·시간: 서버 보정 시각 기준 미래 또는 짧은 허용 범위 내 현재
- 예상 종료 날짜·시간: 시작 이후, 최대 허용 기간 이내
- 예상 학생 수: 1~500명
- 사용할 세트 ID와 세트 제목의 표시용 snapshot

### 상태

- `planned`: 예정
- `live`: 실제 세션 시작됨
- `ended`: 종료됨
- `cancelled`: 취소됨

`planned → live` 전환은 실제 session ID와 연결하며, 실제 시작 시각을 서버 시각으로 기록한다. 종료 시 실제 종료 시각과 등록된 학생 수를 기록한다. 계획 수정은 시작 전 자기 계획에서만 허용하며, 진행 이후에는 실제 기록 필드를 교사가 임의로 줄이거나 바꾸지 못한다.

### 겹침과 경고

두 계획의 시간이 `startA < endB && startB < endA`이면 겹침으로 본다. 취소된 계획은 제외한다.

- 초록: 겹치는 활성 계획이 없거나 예상 합계가 낮음
- 노랑: 겹치는 계획이 있거나 관리자가 정한 주의 인원 이상
- 빨강: 관리자가 정한 혼잡 인원 이상

경계값은 관리자 설정 문서에서 읽되, 규칙은 이 값으로 수업을 거절하지 않는다. 교사는 경고 요약을 확인한 뒤 항상 진행할 수 있다. 경고 확인 시각은 계획 문서에 남겨 나중에 운영 기준을 조정할 수 있게 한다.

## 6. 메인 교사 현황판

승인된 교사가 로그인했을 때만 메인 화면에 `오늘의 수업 현황`을 표시한다.

### 공통 표시

- 현재 진행 중인 수업 수
- 현재 실제 참여 인원 합계
- 오늘 예정·진행 수업 목록
- 시간대별 예상 동시 참여 인원
- 초록·노랑·빨강 혼잡도
- 내 수업 강조와 `계획 수정`, `수업 시작` 바로가기

### 정보 노출

- 일반 교사: 수업 시간, 수업명/반 이름, 예상·실제 인원, 상태
- 관리자: 위 정보와 담당 교사 이름·이메일
- 학생·비로그인 사용자: 현황판 자체를 렌더링하지 않음

일반 교사용 목록 projection에는 소유자 UID·이메일·관리 메모를 넣지 않는다. Firestore 규칙은 쿼리 조건과 문서 형태를 함께 제한하여 클라이언트에서 숨기기만 하는 방식에 의존하지 않는다.

## 7. 데이터 모델

### `teacher_access_requests/{uid}`

- `uid`, `emailCanonical`, `displayName`
- `organization`, `note`
- `status`, `revision`
- `createdAt`, `updatedAt`
- `decidedAt`, `decidedByUid`, `decisionReason`

UID와 canonical email은 인증 토큰과 일치해야 한다. 일반 신청자는 관리자 필드를 쓸 수 없다.

### 기존 승인 교사 문서 확장

- `status: active | suspended | deletion_pending`
- `approvedAt`, `approvedByUid`
- `suspendedAt`, `suspendedByUid`, `suspensionReason`
- `deletionRequestedAt`, `purgeEligibleAt`

기존 `enabled` 필드와의 호환은 additive migration으로 처리하며 strict 규칙 배포 전 전수 감사한다.

### `class_plans/{planId}`

관리자용 원본:

- `ownerUid`, `ownerEmailCanonical`, `ownerDisplayName`
- `setId`, `setTitleSnapshot`, `className`
- `plannedStartAt`, `plannedEndAt`, `expectedStudents`
- `status`, `warningLevel`, `warningAcknowledgedAt`
- `sessionId`, `actualStartedAt`, `actualEndedAt`, `actualParticipants`
- `createdAt`, `updatedAt`

일반 교사용 최소 현황은 개인정보가 빠진 별도 projection 문서 또는 서버가 보장하는 공개 필드 전용 하위 컬렉션으로 제공한다. 한 문서에서 필드만 숨기는 방식은 Firestore 읽기 권한상 안전하지 않으므로 사용하지 않는다.

### 감사 기록

관리자 작업은 append-only 감사 컬렉션에 작업 종류, 대상 UID, 처리 관리자 UID, 서버 시각과 비민감 사유 코드만 기록한다. 이메일·자유 입력 메모를 장기 감사 기록에 복제하지 않는다.

## 8. 보안 규칙과 원자성

- 미승인 사용자는 자기 신청 문서에만 접근한다.
- 승인/거절은 신청 상태 변경과 승인 교사 문서 생성·변경을 하나의 batch/transaction으로 묶는다.
- `active` 교사만 세트 편집, 수업계획 생성, 새 세션 시작이 가능하다.
- 수업계획의 owner UID·email은 인증 정보와 일치하며 생성 후 변경할 수 없다.
- `planned → live`는 연결된 실제 session의 소유자와 setId가 일치할 때만 허용한다.
- 실제 참여 인원은 session/student authoritative count에서 계산해 기록하며 클라이언트 임의 값으로 신뢰하지 않는다.
- 관리자 삭제는 30일 서버 시각, 소유 세트 0건, 진행 세션 0건, 정확한 대상 UID 조건을 모두 만족해야 한다.
- 쿼리가 규칙과 맞지 않아 전체 목록이 permission-denied 되지 않도록 역할별 전용 쿼리와 projection을 테스트한다.

## 9. 무료 우선 운영

- 실시간 listener는 메인 현황판의 오늘 범위와 진행 중 계획에만 둔다.
- 과거 계획은 페이지 조회하며 자동 listener를 만들지 않는다.
- 현황 집계는 클라이언트가 모든 세션을 반복 읽지 않고 계획 projection에 작은 집계 값을 유지한다.
- 계획 종료 후 listener를 해제한다.
- 경고 기준은 운영 경험으로 조정하며 Firebase 무료 한도를 보장하는 숫자로 표현하지 않는다.

## 10. 오류와 복구

- 신청 저장 실패: 입력을 보존하고 재시도 표시
- 관리자 승인 중 부분 실패: 원자 batch로 전체 실패, 신청은 pending 유지
- 계획 충돌 조회 실패: `현황 확인 불가` 경고를 보여주되 사용계획 저장과 수업 진행은 허용
- 계획과 세션 연결 실패: orphan 계획을 live로 만들지 않고 재시도
- 종료 집계 실패: 세션 종료는 유지하고 관리자 재집계 목록에 표시
- 탈퇴 정리 실패: `deletion_pending` 유지, 삭제 gate를 열지 않고 관리자에게 남은 항목 표시

## 11. 마이그레이션과 배포

1. 새 컬렉션 규칙과 emulator 테스트를 먼저 준비한다.
2. 기존 승인 교사 문서를 dry-run 감사하고 새 상태 필드를 additive backfill한다.
3. 감사 결과가 clean일 때 strict 규칙을 배포한다.
4. 교사 신청 UI와 관리자 처리 UI를 배포한다.
5. 수업계획 입력·겹침 경고를 배포한다.
6. 역할별 projection과 메인 현황판을 배포한다.
7. 탈퇴 요청·30일 정리 기능은 소유권 이전과 삭제 gate 검증 후 마지막에 활성화한다.

운영 migration은 기본 dry-run이며 프로젝트 ID, emulator/production mode, report 비덮어쓰기와 원자 보고서 발행을 기존 migration 도구와 동일하게 적용한다.

## 12. 테스트와 수용 기준

### 단위 테스트

- canonical 신청 입력과 상태 전환
- 시간 겹침 경계와 예상 인원 합계
- 경고 단계 계산
- 탈퇴 30일 경계와 소유 세트 gate
- projection에서 개인정보 제거

### Firestore Emulator

- 미승인·승인 교사·관리자·학생별 get/list/create/update/delete 매트릭스
- 신청 승인 batch의 원자성
- 중지된 교사의 편집·새 세션 차단
- 일반 교사가 관리자용 계획 원본을 읽지 못함
- 계획→세션 연결 불변식과 실제 참여 집계 쓰기
- 30일 이전 삭제, 남은 세트·진행 세션 삭제 거부

### 브라우저 수용

- 미승인 교사의 신청·취소
- 관리자 승인 후 같은 사용자의 교사 화면 전환
- 두 교사의 겹친 계획에서 동일 경고 표시와 둘 다 진행 가능
- 일반 교사/관리자 현황판 정보 차이
- 실제 학생 참여 후 현황 숫자 갱신
- 계정 사용 종료 요청·철회·관리자 소유권 처리

### 완료 조건

- 자동 테스트와 Emulator 전체 통과
- 실제 관리자 1명, 일반 교사 2명, 학생 세션 2개의 겹침 시나리오 확인
- 앱 출처 console error 0
- migration 보고서와 배포 순서 기록
- 배포 후 로그인·신청·승인·계획·현황판 smoke test 통과
