# 공동 편집자·휴지통·교사 승인 관리 설계

> 운영 주의(2026-08-22): 이 문서는 역사적 설계/구현 기록이다. 아래의 개별 rollout·deploy 순서는 폐기되었고, production 전체 순서는 오직 [`docs/RELEASE-RUNBOOK.md`](../../RELEASE-RUNBOOK.md)의 R0~R15를 따른다.


## 목표

영상 퀴즈 세트에 소유자가 지정한 공동 편집자를 추가하고, 실수로 인한 손실을 막는 30일 휴지통을 제공한다. 별도 유료 서버 없이 교사와 관리자의 정상 사이트 접속을 정리 실행 기회로 사용한다. 관리자는 사이트 안에서 승인 교사와 역할을 관리할 수 있어야 한다.

## 원칙

- 세트 소유권은 한 명에게 유지한다.
- 공동 편집자는 콘텐츠를 편집하고 수업을 진행할 수 있지만, 소유권·공동 편집자·휴지통 상태는 바꾸지 못한다.
- `admin`도 소유자의 활성 세트를 임의로 편집하거나 휴지통으로 보내지 못한다.
- 휴지통 이동과 복원, 30일 전 즉시 영구 삭제는 소유자만 수행한다.
- 30일이 지난 항목은 소유자 또는 admin이 로그인했을 때 정리한다. 아무도 접속하지 않으면 실제 삭제가 늦어질 수 있음을 화면과 문서에 명시한다.
- 세트 영구 삭제는 세트 본문과 세트 전용 이미지만 제거한다. 기존 수업의 스냅샷·학생·응답·점수·대시보드 기록은 보존한다.

## 데이터 모델

### 세트

`quiz_sets/{setId}`에 다음 선택 필드를 추가한다.

- `trashedAt`: 휴지통으로 이동한 서버 Timestamp. 없으면 활성 세트다.
- `purgeStartedAt`: 영구 삭제가 시작된 서버 Timestamp. 존재하면 복원과 새 편집을 금지한다.
- `collaboratorCount`: 공동 편집자 수를 나타내는 0 이상 20 이하의 정수. 기존 세트는 0으로 간주한다.
- 기존 `ownerUid`, `ownerEmail`, `contentRevision`은 그대로 유지한다.

기존 `archived`는 휴지통과 별개인 개인 목록 숨김 상태로 유지한다. 숨김은 데이터 수명에 영향을 주지 않는다.

### 공동 편집자

`quiz_sets/{setId}/collaborators/{canonicalEmail}` 문서를 사용한다.

```text
email: canonicalEmail
addedByUid: ownerUid
addedAt: server Timestamp
```

- 소유자만 생성·삭제할 수 있다.
- 생성 대상 이메일은 활성 `teacher_allowlist/{canonicalEmail}` 문서가 있어야 한다.
- 세트당 최대 20명으로 제한한다.
- 공동 편집자 생성·삭제는 부모의 `collaboratorCount` 증감과 같은 원자 batch/transaction에 넣고 Rules가 이전값 대비 정확한 `+1` 또는 `-1`과 0..20 범위를 검사한다.
- 자기 자신을 공동 편집자로 추가할 수 없다.
- 공동 편집자는 자신의 이메일 문서를 통해 권한을 얻는다.

### 승인 교사

`teacher_allowlist/{canonicalEmail}`은 다음 형태를 사용한다.

```text
enabled: boolean
role: "teacher" | "admin"
updatedAt: server Timestamp
updatedByUid: adminUid
```

- admin만 목록 읽기와 생성·수정을 수행한다.
- 일반 교사와 학생은 목록을 읽지 못한다.
- 현재 로그인한 admin은 자기 문서를 비활성화하거나 `teacher`로 낮출 수 없다.
- 다른 admin을 비활성화할 때 확인 문구를 요구한다.
- 문서를 물리적으로 삭제하지 않고 `enabled: false`로 비활성화해 감사 가능한 상태를 남긴다.

## 권한 모델

### 활성 세트

- 소유자: 읽기, 편집, 이미지 교체, 수업 진행, 공동 편집자 관리, 숨김, 휴지통 이동.
- 공동 편집자: 읽기, 콘텐츠 편집, 이미지 교체, 수업 진행.
- 다른 승인 교사: 읽기, 사본 만들기, 수업 진행.
- admin: 다른 승인 교사와 동일하다. admin 역할만으로 타인 세트 편집·삭제 권한을 얻지 않는다.
- 학생·미승인 계정: 기존 공개 수업 projection 외 세트 접근 불가.

### 휴지통 세트

- 소유자: 휴지통 목록에서 읽기, 30일 전 복원, 즉시 영구 삭제 시작.
- 공동 편집자와 다른 교사: 목록·직접 읽기·복사·새 수업 시작 불가.
- admin: 만료 전에는 삭제 권한 없음. 30일이 지난 뒤 자동 정리 목적으로만 purge를 시작·재개할 수 있다.
- 진행 중인 기존 세션은 세트 상태와 분리된 스냅샷을 사용하므로 중단하지 않는다.

Firestore Rules는 소유자, 활성 공동 편집자, 휴지통 상태, purge 상태를 각 쓰기마다 다시 확인한다. 이미 열린 편집 화면의 권한이 제거되거나 세트가 휴지통으로 이동하면 이후 저장은 거부된다.

## 휴지통과 영구 삭제 흐름

### 휴지통 이동

1. 소유자가 확인창에서 세트명을 확인한다.
2. transaction이 현재 소유권과 `purgeStartedAt` 부재를 확인한다.
3. 서버 Timestamp로 `trashedAt`을 기록한다.
4. 활성 목록, 검색, 사본 만들기, 새 수업 시작에서 즉시 제외한다.

### 복원

1. 소유자만 실행한다.
2. `purgeStartedAt`이 없고 세트가 아직 존재할 때 `trashedAt`을 제거한다.
3. 원래 숨김 상태는 유지한다.

### 영구 삭제

1. 소유자의 즉시 삭제 또는 30일 만료 정리가 transaction으로 `purgeStartedAt`을 기록한다.
2. purge가 시작된 세트는 복원·편집·복사·새 수업을 모두 차단한다.
3. 공동 편집자 문서와 세트 이미지 문서를 Firestore 제한보다 작은 batch로 반복 삭제한다. purge 상태에서는 새 하위 문서 생성을 Rules가 금지한다.
4. 두 하위 컬렉션을 `limit(1)`로 조회해 비어 있음을 확인하고 같은 purge 세대의 부모를 transaction에서 다시 읽은 뒤 마지막에 삭제한다. purge 시작 뒤 하위 문서 생성이 금지되므로 빈 조회와 부모 삭제 사이에 새 자식이 생기지 않는다.
5. 브라우저가 닫히거나 네트워크가 끊기면 `purgeStartedAt`이 남고 다음 정리 실행이 이어서 처리한다.
6. 세션·스냅샷·학생·응답·점수 문서는 삭제하지 않는다.

즉시 영구 삭제 확인창에는 복구 불가와 삭제 범위를 명시하고 세트명 입력을 요구한다.

## 무료 우선 30일 정리

- 로그인과 승인 상태가 확정된 뒤 백그라운드 정리를 시작한다.
- 일반 소유자는 자신의 만료 세트와 중단된 purge만 조회·정리한다.
- admin은 모든 만료 세트와 중단된 purge를 제한된 페이지 크기로 조회·정리한다.
- 한 화면에서 동시에 하나의 purge만 실행하고, 항목 수와 batch 크기를 제한한다.
- 정리 실패는 앱 진입을 막지 않으며 관리자 화면에 재시도 가능한 경고로 표시한다.
- 30일은 `trashedAt + 30일 <= 서버 보정 현재 시각`으로 판정하고 Rules는 `request.time`으로 최종 검증한다.
- 예약 서버가 없으므로 30일은 최소 보관 기간이며, 접속이 없으면 더 오래 보관될 수 있다.

## 화면 설계

### 세트 목록

- 소유자 카드: `우리 반 시작하기`, `사본 만들기`, `편집`, `공동 편집자`, `파일`, `링크`, `숨기기`, `휴지통`.
- 공동 편집자 카드: `우리 반 시작하기`, `사본 만들기`, `편집`, `파일`, `링크`; `공동 편집 중` 표식.
- 다른 승인 교사 카드: `우리 반 시작하기`, `사본 만들기`.
- 상단에 `휴지통 (N)` 진입 버튼을 둔다.

### 공동 편집자 관리

- 소유자 전용 dialog에서 승인 교사 이메일을 입력한다.
- canonical lowercase 이메일로 정규화하고 승인 목록 존재·활성 상태를 검증한다.
- 현재 편집자 목록, 추가 시각, 제거 버튼을 보여준다.
- 최대 인원, 자기 자신, 중복, 미승인 계정 오류를 구체적으로 안내한다.

### 휴지통

- 세트명, 삭제 시각, 자동 삭제 예정일, 남은 날짜를 보여준다.
- `복원`과 `지금 영구 삭제`를 제공한다.
- purge 진행 중인 항목은 `정리 중`으로 표시하고 복원을 숨긴다.

### 교사 계정 관리

- 관리자 통합 조회에 `교사 계정 관리` 탭을 추가한다.
- 이메일 검색, 역할, 활성 상태, 수정 시각을 보여준다.
- 새 이메일 승인, 역할 변경, 비활성화를 지원한다.
- 현재 admin 자기 계정의 하향·비활성화 버튼은 제공하지 않고 Rules에서도 거부한다.

## 동시성·오류 처리

- 모든 콘텐츠 저장은 저장 직전에 소유자 또는 공동 편집자 권한과 활성 세트 상태를 다시 읽는다.
- 공동 편집자 제거와 저장이 경합하면 Rules가 제거 이후 커밋을 거부한다.
- 휴지통 이동과 콘텐츠 저장은 `contentRevision` 및 상태 조건으로 직렬화한다.
- purge는 idempotent하게 설계해 이미 삭제된 하위 문서를 성공으로 취급한다.
- 세트 부모는 하위 문서 정리가 검증되기 전 삭제하지 않는다.
- 승인 교사 변경은 canonical 이메일 문서만 대상으로 하며 임의 필드를 거부한다.

## 이전과 호환성

- 기존 세트는 `trashedAt`과 `purgeStartedAt`이 없으므로 활성 상태로 간주한다.
- 기존 `archived` 숨김 기능은 유지한다.
- 기존 소유자는 그대로 유지하고 공동 편집자 컬렉션은 비어 있는 것으로 시작한다.
- 기존 세트의 누락된 `collaboratorCount`는 읽을 때 0으로 정규화하고, 첫 공동 편집자 추가 또는 세트 저장 때 명시적인 0..20 정수로 기록한다.
- 현재 두 admin 승인 문서는 새 감사 필드가 없어도 읽을 수 있게 하고, 첫 수정 때 새 형식으로 보강한다.
- 기존 세션은 영구 삭제 후에도 스냅샷 기반으로 조회·재생 가능해야 한다.

## 테스트와 수용 기준

### 단위·브라우저 상태 테스트

- 소유자·공동 편집자·일반 교사별 버튼과 편집 진입 차이.
- 공동 편집자 추가·중복·제거·최대 20명.
- 권한 제거 직후 열린 편집 화면 저장 실패와 안전한 화면 이탈.
- 휴지통 이동·복원·즉시 삭제 확인 흐름.
- 30일 경계 직전/정확히 경계/경과 후 판정.
- purge 중단 후 다음 로그인 재개와 부모 마지막 삭제.
- 승인 교사 추가·역할 변경·비활성화·자기 admin 보호.

### Firestore Emulator

- 소유자만 collaborator create/delete 가능하며 대상 allowlist가 활성 상태여야 한다.
- 공동 편집자는 활성 세트 콘텐츠와 이미지 batch만 수정할 수 있다.
- 공동 편집자는 소유권·공동 편집자·휴지통 필드를 변경할 수 없다.
- 휴지통 세트는 공동 편집자·일반 교사에게 닫힌다.
- 만료 전 admin purge 거부, 30일 후 허용, 소유자 즉시 purge 허용.
- purge 상태에서 restore/edit/copy/session create 거부.
- admin만 allowlist를 관리하고 자기 admin 비활성화·하향 거부.
- 세션·스냅샷·응답·점수가 세트 purge 후에도 보존되고 기존 권한을 유지한다.

### 실제 브라우저

- 두 admin 계정 중 한 계정이 소유 세트에 다른 계정을 공동 편집자로 추가한다.
- 두 계정에서 동일 세트를 순차 편집하고 변경이 동기화된다.
- 공동 편집자 제거 후 저장이 거부된다.
- 휴지통 이동 후 다른 계정 목록·직접 링크·새 수업이 차단된다.
- 복원과 즉시 영구 삭제를 확인한다.
- 테스트용 30일 경계 fixture로 로그인 정리 재개를 확인한다.
- 앱·Firestore console의 신규 warning/error가 없어야 한다.

## 배포 순서

1. lifecycle 이관을 production target dry-run한 뒤 apply하고, durable 최종 감사 보고서의 `safeToDeployStrictRules: true`를 확인한다.
2. 검토된 브랜치를 병합하고 앱을 push한다.
3. 현재 Rules에서 두 admin 계정 로그인을 확인한다.
4. 최종 규칙 파일을 가리키는 staged Rules를 배포한다. gate가 아직 없으므로 counter 종속 쓰기는 fail-closed다.
5. trusted counter gate CLI로 새 `lockId`를 생성해 잠그고 readback `updateTime` generation을 기록한다.
6. 같은 gate identity 아래 counter 이관·감사를 실행하고 durable 보고서의 `safeToDeployStrictRules: true`를 확인한다.
7. strict Rules를 배포한다.
8. counter 감사 보고서의 동일 `lockId`와 `updateTime` generation으로 gate를 해제한다.
9. disposable production smoke를 실행한다. 문제 발생 시 이전 Rules 릴리스와 직전 앱 커밋으로 롤백하며 기존 데이터나 과거 수업 기록은 삭제하지 않는다.

## 제외 범위

- 유료 Cloud Functions·Cloud Scheduler 기반 정시 삭제.
- 공동 소유권 또는 소유권 자동 이전.
- 공동 편집자의 삭제·공동 편집자 관리 권한.
- 휴지통 세트와 연결된 과거 수업 기록의 연쇄 삭제.
- 승인 요청 이메일 발송과 외부 조직 디렉터리 연동.
