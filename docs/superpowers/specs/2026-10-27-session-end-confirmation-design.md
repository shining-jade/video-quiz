# 종료 확인과 오류 안내 최소 변경안

상태: 사용자 승인 (2026-10-27 22:59 UTC). 동일 의미의 앱 내 확인창과 실패 안내·재시도를 구현한다.

## 확인된 근거

- 현재 `plEndSession`은 브라우저 기본 `confirm` 뒤 전체화면 해제, 세션 종료 트랜잭션, 선택적인 수업계획 마무리를 순서대로 기다린다.
- 모든 종료 버튼은 반환 Promise를 처리하지 않는 inline onclick을 사용한다. 저장/계획 마무리 오류 주입 시 오류가 거부되지만 안내 메시지는 0개다. 이것은 격리 재현한 제품의 오류 안내 결함이다.
- 실제 기본 확인창이 열린 두 TEST에서 도구의 클릭/수락/관찰이 CDP focus 명령 시간 초과로 막혔다. 다른 정상 탭과 새 탭은 읽을 수 있었다. 이것은 관찰된 자동화 제약이다.
- 지난 사용자 확인 클릭 후 서버가 live였던 원인은 확인되지 않았다. 사용자 조작 위치나 특정 비동기 단계 실패를 추정하지 않는다.

## 접근 비교

1. 기본 confirm 유지 + 오류 안내만 추가: 제품의 침묵 오류는 개선되지만 현재 자동화 제약과 수동 확인 의존이 남는다.
2. 같은 의미의 앱 내 dialog + 진행/오류 안내: 확인을 유지하고, 도구가 읽고 누를 수 있는 DOM 버튼으로 검증한다. 기존 앱의 dialog 패턴을 재사용한다. 권장안이다.

확인 삭제, 인증 변경, 보안규칙 변경, 브라우저 권한 확대는 범위 밖이다.

## 권장안의 동작

- 모든 기존 종료 버튼이 같은 앱 내 확인 dialog를 연다.
- 제목은 '진행을 종료할까요?', 본문은 '학생 화면은 종료 안내로 바뀌고, 기록은 그대로 남습니다.'를 유지한다. 현재 반 코드와 TEST 이름을 보조 정보로 표시한다.
- '취소'와 '종료 확인'을 제공한다. Escape/취소는 서버 쓰기 없이 닫히고 원래 버튼으로 포커스를 돌린다.
- 확인을 누른 뒤에만 기존 종료 처리를 실행한다. 종료 중 중복 클릭을 막고 '종료 처리 중' 상태를 표시한다.
- 저장 실패는 dialog 안에서 오류를 알리고 같은 세션을 재시도할 수 있게 한다. 세션 저장 후 계획 마무리만 실패하면 두 상태를 구분한다.
- 기존 `endingSession`/`sessionEnded` 차단과 트랜잭션, 결과 보존, 게스트/교사 종료 후 이동은 유지한다.
- 화면을 떠나면 대기 확인을 안전하게 취소한다. 실제 종료가 커밋되기 전에는 성공 안내를 하지 않는다.

## 검증

- 확인/취소/Escape, 중복 클릭, 저장 실패/재시도, 계획 마무리 실패/재시도, 화면 전환, 전체화면 경로를 격리 테스트한다.
- 기존 종료 경합, OX 제출, 동시 입장, 기록 보호의 전체 회귀를 실행한다.
- 배포 후 새 TEST에서 실제 교사 DOM dialog 확인 → 학생 종료 화면 유지 → 늦은 게시 없음 → 참가/응답/채점/점수 해시 보존을 확인한다.
- 현재 지원 브라우저에는 독립 학생 UI 컨텍스트 3개 생성 기능이 없다. 혼합 UI+SDK 검증을 세 브라우저 UI 검증으로 보고하지 않는다.
