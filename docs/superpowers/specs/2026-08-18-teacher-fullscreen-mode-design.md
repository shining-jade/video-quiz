# 교사용 전체화면 진행 모드 설계

## 목표

교사가 전체화면 진행을 시작한 뒤 수업 종료, 홈 버튼, 전체화면 해제 전까지 영상·문제·정답·순위·QR이 하나의 전체화면 컨테이너 안에서 이어지게 한다. 문제 종료 후 `계속 재생`을 눌러도 일반 진행 화면으로 돌아가거나 YouTube 플레이어가 재생성되지 않아야 한다.

## 선택한 구조

현재 교사 진행 화면의 YouTube 플레이어 DOM을 이동하거나 복제하지 않는다. 영상 카드 안에 `#pl-stage` 전체화면 컨테이너를 만들고 기존 플레이어를 그 안에 둔다. 일반 상태에서는 기존 교사 화면의 영상 영역처럼 보이고, 전체화면 상태에서는 CSS가 같은 컨테이너를 화면 전체에 맞춘다.

브라우저 Fullscreen API는 `#pl-stage.requestFullscreen()`으로 진입한다. 지원되지 않거나 호출이 거부되면 같은 컨테이너에 화면 내 확장 클래스를 적용하고 사용자에게 실제 브라우저 전체화면을 사용할 수 없다는 안내를 표시한다.

이 방식은 다음 상태를 자연스럽게 보존한다.

- 현재 영상 재생 위치와 재생·일시정지 상태
- 현재 문항과 완료 문항 배열
- Firestore 학생·응답·live 구독
- 점수와 순위
- 반 코드와 참여 학생
- YouTube 자막과 음량 상태

## 전체화면 진입과 종료

일반 교사 진행 화면의 영상 도구 영역에 `전체화면 진행` 버튼을 추가한다. 사용자가 눌렀을 때만 실제 전체화면을 요청한다.

전체화면 도구 모음에는 다음 버튼을 둔다.

- 홈: 확인 문구를 표시한 뒤 전체화면을 종료하고 같은 교사 진행 화면으로 돌아간다.
- QR: QR 버블을 열거나 닫는다.
- 자막: 기존 `plToggleCC()` 동작을 재사용한다.
- 음량: 음소거와 이전 음량 복원을 전환한다.
- 전체화면 해제: 확인 없이 전체화면만 종료하고 같은 교사 진행 화면을 유지한다.
- 진행 종료: 기존 확인 문구와 `plEndSession()`을 사용한다.

홈 확인 문구는 다음과 같다.

```text
전체화면 진행 화면을 나가시겠습니까?
수업 세션과 학생 응답은 유지됩니다.
```

홈과 전체화면 해제는 세션을 종료하지 않는다. 브라우저의 Esc 또는 시스템 전체화면 해제로 `fullscreenchange`가 발생해도 상태를 삭제하거나 라우팅하지 않고 일반 교사 화면만 복원한다. 다시 `전체화면 진행`을 누르면 같은 플레이어와 중단 지점에서 재진입한다.

## 전체화면 계층

```text
#pl-stage
├─ YouTube 플레이어
├─ 상단 반투명 도구 모음
├─ 하단 진행 정보
├─ 문제 반투명 오버레이
│  └─ 중앙 문제 카드
├─ 순위 오버레이
└─ QR 플로팅 버블
```

레이어 순서는 다음과 같다.

```text
영상 < 진행 정보 < 문제 배경 < 문제 카드 < QR 버블·필수 도구
```

평상시 상·하단 도구는 작고 반투명하게 보인다. 컨테이너에 마우스를 올리거나 포인터·터치 입력이 발생하면 선명하게 표시한다. 키보드 포커스가 도구 안에 있을 때도 선명도를 유지한다.

하단 진행 정보에는 현재 영상 시간, 다음 문항까지 남은 시간, 현재 참여 인원을 표시한다. 기존 `plTick()`과 학생 구독이 같은 DOM 값을 갱신한다.

## 문제와 순위 오버레이

기존 `#overlay`와 `#board-overlay`를 `document.body`가 아니라 `#pl-stage`의 자식으로 생성한다. 전체화면이 아닌 일반 교사 화면에서도 같은 오버레이를 사용하므로 기능이 중복되지 않는다.

문제가 열릴 때 영상은 설정에 따라 일시정지하고, 전체화면 상태에서는 반투명 배경과 중앙 문제 카드를 표시한다. `계속 재생`은 다음 작업만 수행한다.

1. 현재 점수판을 Firestore에 기록한다.
2. live 문항 상태를 닫는다.
3. 문제 오버레이를 제거한다.
4. 같은 YouTube 플레이어에서 재생을 이어간다.

전체화면 해제, 페이지 이동, 플레이어 재생성은 하지 않는다. 다음 문항 시각에 도달하면 같은 `#pl-stage` 위에 다시 문제 오버레이를 표시한다. 순위 오버레이도 컨테이너 안에서 열고 닫는다.

## QR 플로팅 버블

상단 QR 버튼으로 `#pl-qr-bubble`을 열고 닫는다. 버블에는 다음 내용을 표시한다.

- 학생 참여 QR 코드
- 6자리 반 코드
- 프로토콜을 뺀 짧은 참여 주소
- 현재 참여 인원
- 닫기 버튼

QR 생성은 기존 QR 라이브러리와 참여 URL을 재사용한다. QR 버블 조작은 플레이어, 문제 타이머, Firestore 구독과 분리하며 영상 일시정지나 live 변경을 호출하지 않는다.

버블 헤더를 Pointer Events 기반으로 드래그할 수 있게 해 마우스와 터치를 하나의 구현으로 처리한다. 위치는 `pl.qrPosition`에 현재 세션 동안만 저장한다. 드래그와 화면 크기 변경 시 컨테이너 경계 안으로 좌표를 보정한다. 기본 위치는 상단·오른쪽 여백 안쪽이며 문제 중앙 카드를 피한다.

QR 버블은 문제 배경보다 위에 있지만 상단 도구와 같은 필수 제어 계층에 둔다. 교사가 중앙으로 옮길 수는 있으나 화면 밖으로 완전히 이동할 수 없다.

## 상태와 정리

`pl`에 전체화면 UI 상태만 추가한다.

```text
isStageFullscreen
stageFallback
qrOpen
qrPosition { x, y } | null
previousVolume
```

이 상태는 라우트가 유지되는 현재 수업 세션 동안 보존한다. Firestore에 저장하지 않으며 새로고침 후 복구 범위에는 포함하지 않는다. 문제·응답·점수·학생 상태는 기존 Firestore 구조를 그대로 사용한다.

화면 정리 시 Fullscreen API를 안전하게 종료하고 전체화면 이벤트, 포인터 이벤트, 리사이즈 이벤트를 해제한다. 다른 라우트에 전체화면 클래스나 버블이 남지 않게 한다.

## 오류 처리와 접근성

- Fullscreen API 거부 시 화면 내 확장 모드로 전환하고 토스트로 알린다.
- 버튼에는 텍스트 또는 `aria-label`과 `title`을 제공한다.
- QR 버블 닫기와 전체화면 해제는 키보드로 조작할 수 있게 한다.
- 드래그하지 못하는 환경에서도 기본 위치에서 모든 정보를 읽고 닫을 수 있다.
- QR 생성 실패 시 반 코드와 참여 주소는 계속 표시한다.
- 자막이나 음량 API 호출 실패는 진행을 중단하지 않는다.

## 테스트와 완료 조건

자동 테스트는 다음을 검증한다.

- 전체화면 진입이 기존 플레이어 DOM을 재생성하지 않는다.
- 문제·순위 오버레이가 `#pl-stage` 내부에 생성된다.
- `계속 재생`이 전체화면을 종료하지 않고 live만 닫은 뒤 같은 플레이어를 재생한다.
- 홈은 확인 후 전체화면만 종료하고 세션 종료 API나 라우팅을 호출하지 않는다.
- 전체화면 해제와 Esc가 세션 상태를 보존한다.
- QR 열기·닫기가 타이머, live, 플레이어 상태를 변경하지 않는다.
- QR 위치가 드래그와 리사이즈 뒤 컨테이너 안으로 제한된다.
- 음량 토글과 기존 자막 토글이 플레이어 인스턴스를 유지한다.
- 기존 교사·학생·대시보드 테스트가 모두 통과한다.

브라우저에서는 다음 흐름을 확인한다.

1. 테스트 학생을 입장시킨다.
2. 교사 화면에서 전체화면 진행을 시작한다.
3. 자동 또는 직접 열기로 문제를 표시한다.
4. 정답 공개와 순위를 표시한다.
5. `계속 재생` 후 같은 전체화면과 같은 영상 위치가 유지되는지 확인한다.
6. 재생 중과 문제 중에 QR을 열고 마우스·터치 드래그, 닫기, 다시 열기를 확인한다.
7. 홈 확인 후 일반 교사 화면으로 돌아가 세션·응답·영상 위치가 유지되는지 확인한다.
8. 다시 전체화면 진행으로 들어가 이어서 재생되는지 확인한다.
9. 기존 직접 열기, 대시보드, 진행 종료가 동작하는지 확인한다.
