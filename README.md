# 영상 퀴즈 — 실시간 진행 도구

### 👉 https://shining-jade.github.io/video-quiz/

교사가 교실 화면에서 유튜브 영상을 재생하면 미리 지정한 타임코드에 퀴즈가 자동으로 뜨고,
학생들은 각자 폰으로 반 코드만 입력해 **그 순간의 문항만** 푸는 웹 도구입니다.

**콘텐츠(퀴즈 세트)와 진행(반 세션)이 분리**되어 있습니다.
한 선생님이 만든 세트를 링크로 받은 다른 선생님이 각자 반에서 동시에 써도, 반 코드가 달라 응답이 섞이지 않습니다.

정적 HTML과 JavaScript로 동작합니다. 설치나 빌드 과정은 없습니다.

## 저장과 응답 방식

- 퀴즈 편집 화면의 저장 버튼이나 `Ctrl+S`(`Cmd+S`)를 누르면 Firestore에 정식 저장되어 다른 컴퓨터에서도 이어서 편집할 수 있습니다. 단축키 저장은 브라우저 기본 저장을 막고, 현재 스크롤·입력 커서·선택을 유지한 채 현재 위치에 `저장 완료` 알림을 띄웁니다.
- 입력 중인 내용은 현재 브라우저에 임시 초안으로 자동 보관됩니다. 정식 저장 전 초안은 다른 컴퓨터로 옮겨지지 않으며, 새로고침 뒤에는 복구 여부를 묻습니다.
- 학생이 객관식·복수정답·O/X 번호를 누르거나 단답·서술 내용을 입력해도 즉시 제출되지 않습니다. `제출하기`를 눌러 확정하며, 제한시간 전에는 `다시 고르기`로 제출을 취소하고 수정할 수 있습니다.
- 제한시간이 끝날 때 선택하거나 입력한 답이 있으면 자동 제출됩니다. 아무 답도 없으면 미제출로 남습니다.
- 교사 화면은 문항별 `참여 · 제출 · 미제출` 인원과 학생 화면과 동기화된 남은 시간 막대를 표시합니다. 정답과 응답 분포는 공개 전까지 숨깁니다.

## Firebase 설정 (한 번만)

이 도구는 **영상 퀴즈 전용 Firebase 프로젝트** `video-quiz-65798`의 Cloud Firestore를 씁니다.

- 데이터베이스 위치: **싱가포르(`asia-southeast1`)**
- 데이터베이스 모드: **프로덕션 모드**
- Google 애널리틱스, Gemini 학습 데이터 수집: **끔**

프로젝트를 새로 구성할 때는 Firebase 콘솔 → **Firestore Database → 데이터베이스 만들기**에서 위치를 `asia-southeast1`로 선택합니다. 위치는 만든 뒤 바꿀 수 없으므로 먼저 확인하세요.

### 1) Firestore 보안 규칙

저장소의 [`firestore.rules`](./firestore.rules)가 운영 규칙의 원본입니다. Firebase 콘솔 → **Firestore Database → 규칙**에 파일 내용을 붙여넣고 **게시**합니다.

- 교사는 검증된 Google 또는 Email/Password 교사 provider, 정규화 이메일, 현재 UID에 묶인 활성 `teacher_allowances` 승인 문서를 모두 통과해야 합니다. 이메일 인증만으로 교사 권한이 생기지 않습니다.
- 승인 목록과 `teacher_allowances`는 일반 교사와 학생에게 보이지 않습니다. 사용자는 기존 신청 UI로 한 번 요청하고, `admin`은 **관리자 통합 조회 → 교사 계정 관리**의 관리자 승인 UI로 현재 UID·이메일에 맞는 승인 문서를 생성·변경·비활성화합니다. 현재 로그인한 admin 자신은 비활성화하거나 `teacher`로 낮출 수 없습니다.
- 승인 교사는 공유 세트를 수업에 사용하거나 사본을 만들 수 있습니다. 소유자가 **공동 편집자**로 추가한 승인 교사만 원본의 내용·이미지를 편집하고 수업을 진행할 수 있습니다. 공동 편집자는 소유권, 공동 편집자 목록, 숨김, 휴지통 상태를 바꿀 수 없으며 `admin`도 콘텐츠 소유권을 자동으로 얻지 않습니다.
- 학생은 익명 UID로 자기 학생·응답 문서와 세션의 공개 문항만 읽고 씁니다. 원본 세트, 공개 전 정답·해설, 다른 학생 정보와 응답에는 접근할 수 없습니다.
- `admin`만 전체 세션 조회와 보존 기간 삭제를 할 수 있습니다. 퀴즈 세트를 영구 삭제해도 과거 수업의 세션·스냅샷·학생·응답·점수 기록은 보존됩니다.
- 위에 없는 경로는 Firestore의 기본 거부 동작을 따릅니다.

### 2) Google·이메일 교사 로그인과 학생 익명 로그인 설정

공개 퀴즈 자료실은 기존 세트를 자동 공개하지 않는 private by default 기능입니다. 소유자가 게시한 비식별 projection만 승인 교사에게 보이며, 다른 교사는 원본 권한이 아닌 독립 사본을 만듭니다. 휴지통·중지·탈퇴·purge 전 공개 사본 철회, lifecycle gate, index 선배포, Rules-before-app 배포, privacy smoke와 롤백의 authoritative 절차는 [`docs/PUBLIC-QUIZ-LIBRARY.md`](./docs/PUBLIC-QUIZ-LIBRARY.md)를 따르세요. 운영 배포 전에는 새 출력 경로를 지정한 `pnpm audit:public-library -- --project <exact-project-id> --target-mode production --max-documents <bounded-count> --output <new-report>.json` read-only 감사가 완전하고 안전해야 합니다.

Firebase Console에서는 기존 **Google**(교사용)과 **익명(Anonymous)**(학생용)을 유지합니다. **Email/Password**(교사용)는 Firebase Password Policy 최소 길이 8·Enforcement `Require`를 확인하고, 호환 Rules → migration lock/apply → strict UID Rules·정적 앱 → 같은 generation verify → exact unlock을 모두 마친 뒤에만 활성화합니다. 이 순서는 [`docs/EMAIL-TEACHER-AUTH.md`](./docs/EMAIL-TEACHER-AUTH.md)를 따르며 Google이나 Anonymous를 끄지 않습니다. 이메일 가입자는 이메일 인증과 관리자 승인까지 마쳐야 교사 기능을 쓸 수 있고, 학생은 로그인 없이 기존 6자리 반 코드로 입장합니다. 승인된 도메인에는 `shining-jade.github.io`가 있어야 합니다.

교사용 메뉴에서는 Google 로그인 또는 이메일 가입·로그인·비밀번호 재설정을 선택할 수 있습니다. Google과 Email/Password 모두 검증된 provider여야 하며, 미승인·비활성·이메일 미검증 계정은 신청 안내를 봅니다. 사용자가 신청하면 관리자가 승인 UI에서 현재 UID와 canonical 이메일에 결합된 `teacher_allowances`를 생성합니다. 운영자는 legacy email allowlist를 직접 만들거나 수정하지 않습니다. 같은 이메일의 provider 충돌은 계정을 자동 병합하거나 allowance를 복제하지 않고 기존 로그인 방식을 안내합니다. 같은 승인 계정으로 로그인하면 다른 컴퓨터에서도 Firestore에 정식 저장한 같은 세트를 이어서 편집할 수 있습니다. 로컬 자동 초안은 기기 사이에 동기화되지 않습니다. Console 설정, 한국어 이메일 템플릿, 인수와 롤백은 [`docs/EMAIL-TEACHER-AUTH.md`](./docs/EMAIL-TEACHER-AUTH.md)를 따르며, 비밀번호와 재설정 링크는 운영 기록에 남기지 않습니다.

### 3) 기존 데이터 이전

교사 개인 계정 승인과 수업계획 현황판을 배포할 때는 기존 email allowlist를 UID 기반 `teacher_allowances`로 이관하고, 종료되지 않은 세션의 학생 counter를 전수 감사한 뒤 completion gate를 기록해야 합니다. 정확한 backup → Emulator → **호환 head Rules 선배포** → access lock/apply → session join lock/recount/gate → strict Rules·static app → 같은 generation 재검증 → exact unlock → 두 교사·두 수업 browser smoke 순서는 [`docs/TEACHER-ACCESS-CLASS-PLANNING.md`](./docs/TEACHER-ACCESS-CLASS-PLANNING.md)를 따릅니다. 두 apply 보고서가 모두 `safeToDeployStrictRules: true`가 아니거나 lock generation이 배포 뒤 달라졌으면 중단합니다.

엄격한 규칙을 게시하기 전에 기존 `ownerUid` 없는 데이터와 응답의 레거시 정오 필드를 신뢰할 수 있는 Admin SDK 명령으로 이전합니다. 브라우저에서는 이전하지 않습니다. 먼저 대상 Google 계정의 Firebase Authentication UID를 확인하고 관리자 자격 증명이 설정된 로컬 터미널에서 dry-run을 실행합니다.

```powershell
pnpm migrate:legacy -- --project video-quiz-65798 --owner-uid <교사_UID> --output migration-dry-run.json
```

보고서의 실패·감사 실패·모호한 커밋 재확인·남은 응답 누출 수가 모두 0인지 확인한 뒤에만 적용합니다.

```powershell
pnpm migrate:legacy -- --project video-quiz-65798 --owner-uid <교사_UID> --apply --confirm-project video-quiz-65798 --provision-owner-email teacher@school.kr --output migration-apply.json
```

부분 실패 시 같은 명령을 새 출력 파일명으로 다시 실행합니다. 이미 이전된 문서는 건너뛰므로 멱등 재시도가 가능합니다. 최종 보고서의 `safeToDeployStrictRules`가 `true`가 아니면 엄격한 규칙을 게시하지 않습니다. 보고서와 `.reserved` 동반 파일은 운영 감사 자료로 함께 보관합니다.

가져온 직후 원본 데이터를 삭제하지 마세요. Firestore 배포본에서 세트 편집, 이미지, 수업 진행, 학생 응답, 대시보드와 관리자 조회를 확인하고 백업 JSON을 별도로 보관한 뒤 학교의 보관·파기 절차에 따라 원본을 정리합니다. 자세한 절차는 [`FIRESTORE-MIGRATION.md`](./FIRESTORE-MIGRATION.md)에 있습니다.

### 4) 규칙 배포와 롤백

이전 보고서의 배포 게이트와 `pnpm test`, `pnpm test:rules`가 모두 통과한 뒤 `firestore.rules`를 게시합니다. 게시 직전 규칙 원문과 Firebase Console의 직전 릴리스 시각을 기록합니다. 문제가 생기면 데이터를 되돌리거나 재이전하지 말고, Firebase Console → Firestore Database → 규칙 → 릴리스 기록에서 직전 규칙을 복원해 게시한 뒤 원인을 조사합니다.

공동 편집자·휴지통 최초 운영 전환은 다음 순서를 바꾸면 안 됩니다.

1. lifecycle 이관·감사(dry-run → apply → `safeToDeployStrictRules: true`)
2. 병합 및 앱 push
3. 현재 Rules에서 두 admin 로그인 확인
4. staged Rules 배포
5. trusted CLI로 counter gate 잠금
6. counter 이관·감사(`safeToDeployStrictRules: true`)
7. strict Rules 배포
8. 동일 `lockId`와 `updateTimeGeneration`으로 잠금 해제
9. production smoke

Lifecycle CLI도 대상을 명시하고 Emulator 환경 변수가 없는 터미널에서 실행합니다. 출력 파일은 기존 파일을 덮어쓰지 않습니다.

```powershell
pnpm migrate:lifecycle -- --project video-quiz-65798 --target-mode production --output lifecycle-dry-run.json
pnpm migrate:lifecycle -- --project video-quiz-65798 --target-mode production --apply --confirm-project video-quiz-65798 --output lifecycle-apply.json
```

그 뒤의 잠금·counter 이관·해제 명령과 보고서 판정은 [`docs/COUNTER-MIGRATION.md`](./docs/COUNTER-MIGRATION.md)를 그대로 따릅니다. lifecycle 또는 counter 최종 보고서가 안전하지 않으면 다음 단계로 넘어가지 않습니다.

## 배포 — GitHub Pages

**현재 기존 사이트 주소:** https://shining-jade.github.io/video-quiz/

자동 테스트를 통과한 변경만 배포합니다. 프로덕션 데이터 이전은 미실행이며, 엄격한 규칙 게시·사이트 배포와 실제 브라우저 인수 검증은 남아 있습니다. Firebase Console의 Email/Password 설정과 실제 계정/메일 인수는 별도 운영 gate이며, [`docs/EMAIL-TEACHER-AUTH.md`](./docs/EMAIL-TEACHER-AUTH.md)의 pre-deploy 절차를 완료하기 전에는 실행하지 않습니다.

저장소는 [shining-jade/video-quiz](https://github.com/shining-jade/video-quiz) (Public), `main` 브랜치 루트를 Pages가 서비스합니다.

### 수정한 내용을 반영하려면

1. `node --test tests/*.test.js`로 자동 테스트를 통과시킵니다.
2. `firestore.rules`를 Firebase 콘솔에 게시합니다.
3. 바탕화면 `영상퀴즈` 폴더에서 변경을 커밋하고 푸시합니다.

```bash
git add -A && git commit -m "수정 내용" && git push
```

1~2분 뒤 사이트에 반영됩니다. 배포 주소를 새로고침한 뒤 교사 창과 학생 창을 각각 열어 다음을 확인합니다.

- 승인 교사 Google 로그인과 미승인 계정 거부가 정상인지
- 세트 조회·저장과 이미지 표시가 되는지
- 반 코드 발급, 학생 입장, 문항 열기·제출·정답 공개가 실시간으로 이어지는지
- 두 창의 남은 시간이 1초 이내로 맞는지
- 관리자 조회와 기간 삭제가 정상인지
- Firebase 콘솔의 Firestore 사용량과 권한 거부 오류가 예상 범위인지

> 로컬에서 `index.html` 을 더블클릭해 열어도 동작합니다. 다만 그때 만들어지는 공유 링크는 그 PC에서만 열리는 주소이므로, 실제 수업에는 위 Pages 주소를 쓰세요.

## 사용법

### 1. 퀴즈 세트 만들기 (한 번만, 만드는 사람)

`.../#/make` 로 들어가거나 첫 화면에서 **[퀴즈 세트 만들기]** 를 누릅니다.

1. 세트 제목을 입력하고 첫 번째 **영상 카드**에 유튜브 주소를 붙여 넣습니다. 주소는 `watch?v=`, `youtu.be/`, `/shorts/`, `/embed/` 어떤 형태든 됩니다. **[＋ 다음 YouTube 영상 추가]**로 영상을 더 연결할 수 있습니다.
2. 영상 카드의 **[↑ 위로]·[↓ 아래로]**로 재생 순서를 바꾸고, **[복사]**로 영상과 소속 문항을 함께 복제합니다. **[삭제]**는 확인 후 그 영상과 소속 문항을 함께 지우며, 마지막 영상 한 개는 삭제할 수 없습니다. **[미리보기 선택]**을 누르면 해당 카드의 플레이어가 열립니다.
3. 각 영상의 **시작 시각·종료 시각**은 `분:초` 칸에 직접 입력하거나 두 개의 슬라이더로 조절합니다. 시작과 종료 사이가 실제 재생 구간이며, 문항 시각도 이 범위 안에 있어야 저장됩니다.
4. 각 카드에서 영상을 재생하다가 원하는 지점에서 **[📍 현재 시각으로 문항 추가]** 를 누르면 그 영상에 문항이 만들어집니다. 문항 시각은 직접 입력하거나 영상 아래 **문항 타임라인의 번호 점을 드래그**해 바꿀 수 있습니다. 타임라인의 양 끝은 영상 전체가 아니라 설정한 시작·종료 시각입니다. 문항 제목 버블은 같은 영상 안이나 다른 영상으로 드래그해 순서를 옮길 수 있고, 포커스한 버블에서 `↑`·`↓`(다른 영상은 `Alt+↑`·`Alt+↓`)로도 같은 기능을 제공합니다. 다른 영상으로 옮길 때는 기존 재생 구간의 상대 위치를 새 영상 구간에 맞춰 문항 시각으로 바꾸므로, 중간 지점 문항은 새 영상의 중간 지점에 놓입니다.

   문항 번호는 영상별로 다시 시작하지 않고 **전체 영상에 걸쳐 1번부터 연속**됩니다. 진행 화면의 타임라인은 현재 영상의 문항만 표시하되 이 전체 번호를 유지합니다.

   편집 중에는 **[↶ 실행 취소]** 또는 `Ctrl+Z`(`Cmd+Z`)로 최근 변경을 되돌리고, `Ctrl+Shift+Z`/`Ctrl+Y`(`Cmd+Shift+Z`/`Cmd+Y`)로 다시 실행할 수 있습니다. 저장이 성공하면 이력은 새 기준점으로 정리됩니다.

5. 편집 화면은 **왼쪽 영상 / 오른쪽 문항**으로 나뉩니다. 문항을 추가하면 오른쪽에 만들어지고 **질문 칸에 커서까지 들어가므로** 바로 타이핑하면 됩니다.

   영상은 스크롤해도 왼쪽에 그대로 붙어 있으므로, 문항을 몇 개를 만들든 영상을 보러 위로 올라갈 일이 없습니다. **진행 설정**은 한 번 정하고 마는 값이라 한 줄로 접혀 있고 [설정 바꾸기]로 펼칩니다.

   가운데 경계선을 **끌어서 영상과 문항 칸의 폭을 바꿀 수 있습니다.** 정한 폭은 그 브라우저에 기억되고, 경계선을 두 번 클릭하면 기본값으로 돌아갑니다.
6. 문항 유형을 고르고 내용을 채웁니다.

| 유형 | 채점 | 설명 |
|---|---|---|
| 객관식 | 자동 | 보기 2~6개, 왼쪽 동그라미로 정답 지정 |
| 복수 정답 | 자동 | 정답을 모두 체크. 학생이 고른 것이 **정확히 같아야** 정답 |
| O · X | 자동 | 보기 문구는 직접 고쳐도 됩니다. 학생 화면에는 큼직한 O·X 로 나옵니다 |
| 단답형 | 자동 | 인정할 표현을 한 줄에 하나씩. 띄어쓰기·대소문자·마침표는 무시하고 비교 |
| 서술형 | **교사** | 수업이 끝난 뒤 대시보드에서 O/X 를 눌러 채점. 그 전에는 미채점으로 집계 |

**이미지**도 문항마다 넣을 수 있습니다. 사진 파일을 올리면 브라우저가 알아서 줄여 저장하고(3MB 사진 → 약 30KB), 외부 이미지 주소를 붙여넣어도 됩니다.
7. **[세트 저장하고 링크 만들기]** → 공유 링크가 나옵니다. 이 링크를 다른 선생님께 전달하세요.

문항이 여러 개가 되면 화면 오른쪽에 **문항 목차**가 뜹니다. 항목을 누르면 그 문항으로 바로 이동하고, 옆의 ▲▼로 순서를 바꿉니다. (화면 너비가 좁으면 자리가 없어 숨겨집니다.)

### 1-2. 이미 만든 세트 다시 쓰기 — `#/sets`

첫 화면의 **[만들어진 세트 목록]** 에서 학교 안에 만들어진 세트를 모두 볼 수 있습니다.

| 버튼 | 하는 일 |
|---|---|
| ▶ 진행 | 그 세트로 바로 우리 반을 시작합니다 |
| ✏️ 편집 | 소유자 또는 소유자가 지정한 공동 편집자가 내용을 고칩니다. 공동 편집자의 변경도 그 세트를 쓰는 모든 선생님에게 반영됩니다 |
| ⧉ 복제 | **원본은 그대로 두고** 사본을 만들어 우리 반용으로 고쳐 씁니다 |
| 🔗 링크 | 공유 링크를 복사합니다 |
| 🗂 숨기기 | 목록에서만 감춥니다. 기록도 링크도 살아 있고, [숨긴 세트도 보기]로 되돌립니다 |
| 👥 공동 편집자 | 소유자가 승인 교사를 최대 20명까지 추가하거나 해제합니다 |
| 🗑 휴지통 | 소유자가 세트를 휴지통으로 옮깁니다. 휴지통에서는 복원하거나 세트명 입력 후 즉시 영구 삭제할 수 있습니다 |

`숨기기`는 내 목록에서만 가리는 기능이고, `휴지통`은 세트의 삭제 예약입니다. 휴지통의 세트는 공동 편집자와 다른 교사의 목록·직접 열기·사본·새 수업에서 즉시 제외됩니다. 소유자만 30일 안에 복원하거나 즉시 영구 삭제를 시작할 수 있습니다.

휴지통의 **30일은 최소 보관 기간**입니다. 무료 운영 방식이라 예약 서버가 없으므로 소유자나 관리자가 **접속할 때 자동 정리**되며, 아무도 접속하지 않으면 실제 삭제는 더 늦어질 수 있습니다. 정리 중 네트워크가 끊겨도 다음 로그인에서 이어서 처리하며, 휴지통의 `정리 재시도`를 사용할 수 있습니다. 영구 삭제 범위는 세트 본문·세트 전용 이미지·공동 편집자 문서뿐이고, **과거 수업 기록은 보존**됩니다.

**진행 설정** (이 세트로 진행하는 모든 반에 공통 적용)

| 설정 | 설명 |
|---|---|
| 정답 공개 시점 | `제출 즉시` / `타이머 종료 후 자동` / `교사가 버튼 누를 때` / `학생에게 공개 안 함` |
| 문항당 응답 제한 시간 | 초 단위. **0이면 무제한** — 교사가 [계속 재생]을 누를 때까지 열려 있습니다. |
| 정답 자동 공개까지 | `타이머` 모드에서 퀴즈가 뜬 뒤 몇 초 후에 정답을 보여줄지 |
| 퀴즈가 뜰 때 영상 | 자동 일시정지 / 계속 재생 |

문항마다 제한 시간을 다르게 주고 싶으면, 각 문항의 *"이 문항만 제한 시간 다르게"* 칸을 채우면 됩니다. 비우면 세트 기본값을 씁니다.

### 2. 수업에서 진행하기 (진행하는 선생님)

1. 공유받은 세트 링크를 교실 컴퓨터에서 엽니다.
2. 반 이름(선택)을 적고 **[🚀 우리 반 시작하기]** → 6자리 반 코드가 발급됩니다.
3. 화면 오른쪽의 **반 코드와 QR** 을 학생들에게 보여줍니다.
4. 첫 영상은 그 카드의 **시작 시각**부터 재생합니다. 지정한 시각이 되면 영상이 멈추고 퀴즈가 화면 가득 뜹니다.
   - 공개 전에는 **제출 인원만** 보입니다. 이 화면은 교실 앞에 투사되므로 정답 표시도, 보기별 응답 분포도 감춰 둡니다. (둘 다 답을 알려주는 단서가 됩니다.)
   - **[✅ 정답 공개]** — 그때 정답·분포·해설이 학생 화면과 교실 화면에 함께 뜹니다.
   - 타이머 모드에서는 시간이 차면 교실 화면도 학생 화면과 **같은 순간에** 자동 공개됩니다.
   - **[▶ 계속 재생]** — 퀴즈를 닫고 영상을 이어서 재생합니다. 방금 끝낸 같은 문항이 반복해서 다시 열리지 않습니다.
   - 응답 분포를 미리 보고 싶으면 **대시보드**를 다른 창(두 번째 모니터)에 띄워 두세요.
5. 왼쪽 문항 목록에서 시각을 누르면 그 지점으로 이동하고, **[열기]** 로 영상과 무관하게 문항을 직접 띄울 수도 있습니다.

**전체화면 진행**을 누르면 16:9 플레이어가 화면 중앙에 맞춰지고 영상·문제·정답·순위가 같은 stage 안에서 이어집니다. 문제와 순위 오버레이도 stage 중앙에 놓입니다. **[▶ 계속 재생]**은 문제만 닫으며 같은 YouTube iframe, 전체화면 상태와 영상 위치를 유지합니다. 상단 **[QR]** 버튼으로 참여 QR을 열고 화면 안에서 드래그할 수 있습니다. QR을 열고 닫거나 움직여도 재생과 퀴즈 타이머는 초기화되지 않습니다. 홈과 전체화면 해제는 수업 세션을 종료하지 않습니다.

플레이어 아래 **퀴즈 타임라인**은 현재 영상의 시작·종료 구간을 0~100%로 사용합니다. 진행 막대와 문항 마커가 같은 구간 계산을 쓰며, 완료·현재·예정 문항과 다음 문항까지 남은 시간을 보여 줍니다.

재생 중 문항 시각을 앞으로 가로지르거나 타임라인을 그 시각 뒤로 이동하면 해당 퀴즈가 열립니다. 이미 끝낸 문항은 계속 재생 직후에는 다시 열리지 않지만, 문항 시각보다 **1초 이상 앞**으로 되감은 뒤 다시 앞으로 지나가면 다시 출제됩니다.

영상의 종료 시각에 도달했을 때 열린 문제가 없다면 **3초 전환 안내** 뒤 다음 영상의 시작 시각부터 자동 재생합니다. 문제가 열려 있으면 먼저 답안 처리와 **[▶ 계속 재생]**을 마쳐야 전환합니다. 마지막 영상이 끝나면 **모든 영상 재생 완료** 메뉴가 열리고 순위 보기, 대시보드, 처음부터 다시 보기, 진행 종료를 선택할 수 있습니다. 이 완료 화면만으로는 학생 세션이 끝나지 않으며, **[진행 종료]**를 눌렀을 때만 종료됩니다.

> 💬 **자막** — 유튜브 자동 생성 자막이 영상 아래를 가리는 경우가 많아 **기본은 꺼져 있습니다.** 선택은 그 브라우저에 기억됩니다.
> 자막을 보고 싶으면 **[💬 자막 허용]** 을 누른 뒤, 플레이어 오른쪽 아래 **⚙(설정) → 자막**에서 원하는 자막을 고르세요.
> (끄는 것은 도구가 확실히 처리하지만, 특정 자막을 켜는 것은 유튜브 쪽 제약으로 영상마다 달라 플레이어 메뉴에 맡깁니다.)
6. 수업이 끝나면 **[진행 종료]** 를 누릅니다. 학생 화면이 종료 안내로 바뀝니다.

**실시간 순위** — 오른쪽 사이드바에 학생별 맞힌 개수와 순위가 실시간으로 쌓입니다. **[🏆 크게 보기]** 를 누르면 교실 화면에 띄우기 좋은 큰 순위표가 뜹니다(1~3등은 메달). 퀴즈가 떠 있을 때도 오버레이의 **[🏆 순위]** 로 바로 볼 수 있습니다. 동점은 같은 등수로 묶이고, 채점 전 서술형은 점수에서 빠집니다.

> 순위표는 교사 화면에만 있습니다. 언제 교실에 띄울지는 선생님이 정하시면 됩니다. 학생 화면에는 자기 순위만 조용히 보입니다.

> 영상을 뒤로 되감으면 지나간 문항이 **다시 발화**합니다. 앞으로 건너뛰면 지나친 문항은 건너뜁니다.

### 3. 학생

1. 첫 화면에서 **[학생 참여하기]** → 6자리 반 코드 입력 (QR을 찍으면 코드가 자동으로 채워집니다)
2. 학년·반·번호·이름을 입력하고 입장 → 대기 화면
3. 선생님이 퀴즈를 열면 자동으로 문항이 뜹니다. 답을 고르면 바로 제출됩니다.
4. 학생 화면에는 **영상이 나오지 않습니다.** 교실 앞 화면을 보게 하기 위한 의도된 동작입니다.
5. 퀴즈 사이사이 대기 화면에 **맞힌 개수 · 남은 문항 · 내 순위**가 보입니다. 정답 공개를 "끝까지 비공개"로 설정한 세트에서는 점수와 순위 대신 제출 개수만 보입니다.

> 학생 화면은 **점수 요약만** 받아 순위를 계산합니다. 다른 학생이 무엇을 골랐는지는 내려받지 않으므로, 개발자도구를 열어도 남의 답을 미리 볼 수 없습니다.

같은 학년·반·번호로 다시 들어오면 같은 학생으로 이어집니다. 새로고침하거나 폰을 바꿔도 이미 낸 답이 유지됩니다.

### 4. 실시간 대시보드 (진행 교사)

진행 화면 상단의 **[📊 대시보드]** — 새 탭으로 열어 두 번째 모니터에 띄워 두면 좋습니다.

- 문항별 선택 분포, 정답률, **미응답자 명단**
- 학생별 O/X 표, 총점, 평균 반응속도 (머리글 클릭으로 정렬)
- **서술형 채점** — 서술형 문항을 펼치면 학생이 쓴 답이 모두 나옵니다. 각 답 오른쪽 **O / X** 를 누르면 점수와 정답률에 바로 반영되고, [되돌리기]로 미채점으로 돌릴 수 있습니다
- 단답형도 펼치면 학생이 실제로 뭐라고 썼는지 그대로 보입니다
- CSV 내려받기 (엑셀에서 한글이 깨지지 않습니다. 텍스트 답안과 미채점 표시 포함)

### 5. 관리자 통합 조회

`.../#/admin` — 승인 목록에서 `role: "admin"`인 Google 계정만 접근할 수 있습니다.

- 기간·세트·학년·반으로 걸러 **전체 반을 가로질러** 조회

- 학생 이름을 누르면 개인 누적 이력 (세션별 점수)
- ⚙ 관리 탭에서 화면에 고정된 300건 이하 조회 결과의 **기간 지정 삭제**

## 개인정보 처리

이 도구는 **학년·반·번호·이름**과 문항별 응답을 Firebase에 저장합니다. 개인정보 처리에 해당합니다.

- 학생 화면 하단에 수집 항목·목적 고지 문구가 표시됩니다.
- 관리자 화면은 승인된 `admin` Google 계정과 Firestore 규칙으로 보호됩니다. **공용 PC에서는 반드시 로그아웃하세요.**
- 보관 기간이 지난 자료는 관리자 → ⚙ 관리 → **[이 기간 기록 삭제]** 로 파기합니다. 조회 기간에 걸린 진행 기록·학생 응답·반 코드가 함께 지워지고, 퀴즈 세트 자체는 남습니다.
- 학교 개인정보 보호 방침에 맞춰 보관 기간을 정해 운영하세요.

## Firestore 사용량과 읽기 절감 원칙

Cloud Firestore는 문서 읽기·쓰기·삭제 횟수와 저장량을 기준으로 사용량을 계산합니다. 운영 중에는 [Firebase 콘솔의 사용량 화면](https://console.firebase.google.com/project/video-quiz-65798/usage)을 정기적으로 확인하세요.

- 학생 화면은 `sessions/{sessionId}/meta/live` 문서만 실시간 구독합니다.
- 퀴즈 세트는 입장할 때 한 번 읽고 계속 구독하지 않습니다.
- 학생 응답은 학생별 문서에 모아 다른 학생의 답을 내려받지 않습니다.
- 순위 요약은 문항을 닫을 때 갱신하고, 관리자 전체 조회는 필요할 때만 실행합니다.

이 경계를 넓히면 참가자 수만큼 읽기가 반복될 수 있으므로 새 기능을 추가할 때도 유지해야 합니다.

### 알아 두어야 할 보안 경계

- 승인된 교사는 공유 수업과 사본 생성을 위해 다른 승인 교사의 원본 세트(정답·해설·세트 이미지 포함)를 읽을 수 있습니다. 학생과 미승인 사용자는 읽을 수 없습니다.
- 학생 익명 UID는 브라우저 설치별 식별자입니다. 같은 학년·반·번호를 입력해도 다른 UID가 기존 응답을 덮을 수 없습니다.
- 공개 전 학생 화면은 `meta/live.publicQuestion`만 읽고, 정답·해설은 `revealed: true`가 된 뒤 공개 projection으로 받습니다. 학생의 정오 판정과 점수는 교사 전용 문서에 저장됩니다.
- 승인 목록 변경, 레거시 이전, 엄격한 규칙 배포는 웹 UI가 아니라 Firebase Console 또는 신뢰할 수 있는 Admin SDK 환경에서만 수행합니다.

## 데이터 구조

```
quiz_sets/{setId}                           퀴즈 세트 문서 (videos[]와 진행 설정 포함)
    videos[]                                { videoId, videoUrl, startSec, endSec, questions[] }
images/{setId}/q/v{영상번호}q{문항번호}       압축한 문항 이미지 문서 (예: v0q0, v1q2)
codes/{CODE}                                반 코드 → 세션 역인덱스
sessions/{sessionId}                        반 세션 기본 정보
    meta/live                               현재 문항 신호 (q, openedAt, revealed, limitSec)
    meta/board                              학생별 점수 요약
    students/{학생_익명_UID}                 참여 학생
    responses/{학생_익명_UID}                학생 한 명의 공개 답안 상태
    grades/{학생_익명_UID}                   교사 전용 정오·점수
teacher_allowances/{Firebase_UID}            UID·canonical 이메일에 결합된 권위 교사 승인과 teacher/admin 역할
teacher_allowlist/{검증된_이메일}            이전 기간에만 쓰는 Google 전용 legacy 호환 mirror
clock/{sampleId}                            서버 시각 보정용 임시 문서
```

이전 단일 영상 문서의 최상위 `videoId`·`videoUrl`·`questions[]`는 읽을 때 자동으로 `videos[0]`으로 변환하며, 재생 구간은 `startSec: 0`, `endSec: null`로 간주합니다. 예전 숫자 이미지 키 `0`, `1`, …도 첫 영상의 `v0q0`, `v0q1`, …로 정규화하고, 읽기 때는 기존 문서를 한 번 더 찾아 이전 세트와 호환됩니다.

### 타이머가 기기마다 어긋나지 않는 이유

앱이 시작될 때 `clock` 임시 문서에 Firestore 서버 타임스탬프를 쓰고 되읽어 로컬 시계와의 차이를 계산한 뒤 문서를 삭제합니다. 퀴즈를 열 때도 `openedAt`에 서버 타임스탬프를 기록하므로 각 기기가 같은 기준으로 남은 시간을 계산합니다.

> 참고: 이 프로젝트를 만든 PC의 시계는 실제로 서버보다 약 5초 빨랐습니다. 각 기기의 `Date.now()` 를 그대로 썼다면 타이머가 5초 어긋났을 상황입니다.

## 문제가 생기면

| 증상 | 원인과 해결 |
|---|---|
| 학생 입장에서 익명 인증 오류가 남 | Authentication → Sign-in method → 익명을 사용 설정하세요. |
| 교사 메뉴에서 승인되지 않았다고 나옴 | 지원 provider, 이메일 검증 상태, 현재 Firebase UID 경로의 `teacher_allowances/{uid}`가 같은 canonical 이메일·활성 status·`teacher`/`admin` role인지 확인하세요. password 계정에 legacy email allowlist를 만들어 우회하지 마세요. 승인 문서는 웹에서 직접 읽을 수 없는 것이 정상입니다. |
| 저장이 안 되고 `permission-denied`가 보임 | 로그인한 교사가 세트 소유자인지, 승인 문서가 활성인지, 이전 보고서가 배포 안전 상태인지와 현재 게시 규칙 버전을 확인하세요. |
| 영상이 안 나옴 | 학교 네트워크가 유튜브를 차단했을 수 있습니다. 교사 PC에서 유튜브가 열리는지 확인하세요. |
| 영상이 저절로 재생되지 않음 | 브라우저 정책상 첫 재생은 사람이 눌러야 합니다. 재생 버튼을 한 번 눌러 주세요. |
| 자막이 그래도 뜬다 | 광고가 재생되는 동안에는 자막 제어가 먹지 않습니다. 광고가 끝나면 꺼집니다. 그래도 남아 있으면 유튜브 플레이어의 ⚙(설정) → 자막 → 사용 안 함을 한 번 눌러 주세요. 유튜브가 그 브라우저에 기억합니다. |
| 학생이 반 코드를 넣어도 "그런 반 코드가 없습니다" | 코드는 대소문자 구분 없이 6자리입니다. `0/O`, `1/I` 는 애초에 코드에 쓰지 않으므로 헷갈리면 다시 확인하세요. 진행을 종료한 반의 코드도 그대로 유효합니다. |
| 학생 화면에 퀴즈가 안 뜸 | 학생과 교사가 **같은 반 코드**인지 확인하세요. 다른 선생님의 반 코드로 들어가면 그 반 신호만 받습니다. |
| QR이 안 보임 | QR 라이브러리를 못 불러온 경우입니다. 아래 참여 주소를 불러 주거나 코드를 직접 입력하게 하세요. |
